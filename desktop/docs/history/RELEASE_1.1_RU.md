# MonoPod Desktop 1.1 — совместимость с firmware 0.10.6 / MPOD1 v4

Дата: 31.10.2026. Приложение: 1.1.0, File/Assembly Version: 1.1.0.0.
Исходники обновлены в `I:\DIY_iPod_Mono\MonoPod_Desktop`.

## Что исправлено

- **Установка темы по Wi-Fi.** Прежний Desktop отправлял тему в `/api/fs/upload?theme=1`. Прошивка 0.10.6 распознаёт тему только по URI `/api/theme`; общий файловый маршрут отклонял `/MonoPod/theme.mpt` как `PROTECTED_PATH`. Теперь используется специальный `/api/theme?size=...&crc=...&replace=1` с CRC всего файла. Проверка MPT выполняется и перед отправкой.
- **Предпросмотр и отправка темы.** Параллельные обновления предпросмотра сериализованы. Устаревший расчёт глифов не заменяет импортированную или прочитанную тему. Отправка, экспорт и сохранение профиля дожидаются актуального результата. При ошибке чтения с плеера частичные или повреждённые данные не выдаются за готовую тему.
- **Сессии синхронизации.** Раскрытие каталогов сначала подтверждает Sync. USB Start и явный End сверяют состояние плеера, включая потерю прежней сессии или SD. Wi-Fi Start проверяет актуальные сведения и наличие SD; End не запрашивает данные после остановки сервера. Представления и состояние подключения очищаются при завершении или обрыве.
- **Продолжение работы после темы.** Установка больше не выключает Sync автоматически. После неё можно работать с файлами; освобождение плеера выполняется кнопкой **End Sync** или **Disconnect**.
- **Подтверждения и ошибки транспорта.** Для v4 HTTP 200 считается успехом только с JSON `{"ok":true}`. USB проверяет конкретные ответы `SYNC_STARTED`, `SYNC_ENDED`, `SAVED`, а не любой префикс `OK`. Ошибка приёма бинарного блока закрывает неопределённый поток; текстовые команды в него не добавляются. Локальное закрытие USB выполняется вне UI-потока с коротким ограниченным ожиданием.
- **Native CDC.** После открытия порта предусмотрена пауза 0,5 с, как в probe прошивки, для установления DTR/CDC. HELLO допускает более 16 посторонних строк в пределах общего таймаута. Это не автоматическое определение правильного физического порта: USB-UART остаётся диагностической консолью.
- **Версия.** Заголовок, About, журнал, manifest и версии Desktop/Core обновлены до 1.1.

Wire-format MPOD1 v4 между 0.10.0 и 0.10.6 не менялся. Причиной подтверждённого отказа Wi-Fi темы был маршрут клиента, а не новая версия бинарного формата. Форматы MPT1/MPT2 сохранены.

## Запуск и обновление

Обычная папка запуска обновлена: `publish/win-x64/MonoPod.Desktop.exe`.
Отдельная чистая сборка: `publish/win-x64-1.1/MonoPod.Desktop.exe`.
Portable-архив: `outputs/MonoPod_Desktop_1.1_win-x64.zip`.
Распакуйте его целиком и запускайте EXE рядом с остальными DLL. Устанавливать .NET отдельно не требуется.

Для USB выберите **Native USB CDC**. Для Wi-Fi сначала включите Wi-Fi Sync на плеере и используйте его адрес. После аварийного обрыва USB-передачи подождите 18 секунд перед повторным соединением. Если последнее подтверждение потерялось, сначала проверьте состояние файла на плеере.

Исходная прошивка 0.10.6, прежние версии и Legacy Studio не изменялись. Копии исходников Desktop до обновления и прежних опубликованных файлов сохранены в `work/desktop-1.1-2026-10-31/`.

## Границы проверки

Физический ESP32-S3 не подключался для этих проверок. Реальные USB/Wi-Fi передачи, SD, применение темы на дисплее и поведение при отключении питания ещё требуют проверки на плеере. Прошивка не прошивалась и полный Arduino-build 0.10.6 в этой работе не выполнялся. Исторические `firmware-builds` и отчёты 1.0 относятся к прежней ревизии и не являются новыми результатами.

# 1. Назначение и статус

MonoPod — автономный музыкальный плеер с интерфейсом, вдохновлённым ранними iPod. На **текущем макете** используется **ESP32-S3 N16R8** с двумя USB-C, ST7735S 1.8" (160×128 после поворота), microSD, PCM5102A, TDA1308, ёмкостным 6-секторным Click Wheel, пятью кнопками через ADC1, HOLD, аккумулятором 1S ~1000 мА·ч, **TP4056** и звуковым пассивным пьезоэлементом.

**Никакого haptic-привода, вибромотора, DRV2605L и дополнительного энкодера в прототипе нет.** Пьезоэлемент выдаёт **звук щелчка**, а не вибрацию. Вариант с DRV2605L + LRA — **только будущая интегрированная PCB (Rev. B)** и может заменить пьезо.

Прошивка v0.8.3 находится в стадии **экспериментального прототипа**: программные тесты не заменяют аппаратную отладку и полную Arduino-компиляцию. Безопасное питание и диагностика аналогового тракта обязательны до установки в корпус.

| Подсистема | Сейчас | Требует проверки на плате |
|---|---|---|
| Экран / меню / темы | Исходники ST7735 и Studio | Физический ST7735, подсветка, контраст |
| microSD / медиатека | FAT32, `MAX_TRACKS=2048` | 1024+ реальных треков, потребление RAM/PSRAM |
| Аудио | I²S → PCM5102A → TDA1308 | DC на выходах, питание/осциллограмма/нагрузка |
| Управление | 6 touch + кнопки ADC1 + HOLD | Калибровка ёмкостных секторов |
| Bluetooth A2DP/AVRCP | Отсутствует в сборке S3 | Только на классической ESP32; для S3 аппаратно недоступно |
| USB Sync v1 | Реализация CDC → microSD + Studio/CLI | Сборка ESP32-S3, обнаружение COM-порта, передача реальных файлов |
| Wi-Fi Sync | Отдельный HTTP-сервис | Wi-Fi upload на физическом железе |
| Зарядка | Модуль TP4056 | Ток заряда, защита, питание DC/DC |

# 2. Границы ревизий

**Rev. A (тестовый стенд):** питание от USB самой DevKit, без аккумулятора; экран, SD, аудио, кнопки, колесо, пьезо. Сначала запускается микроконтроллер, потом периферия по одной.

**Rev. A-P (текущий автономный макет):** добавлены аккумулятор 1S, модуль TP4056, защита, выключатель и отдельный DC/DC 3,3 В. Зарядка при выключенном плеере. USB-C ESP32-S3 для прошивки/синхронизации, USB зарядника TP4056 — отдельная цепь, **не соединять 5 В разных USB параллельно**.

**Rev. B (будущая PCB):** собственная компоновка, возможны BQ24074 с power-path и DRV2605L/LRA вместо пьезы, единственная основная USB-C коммутация после отдельного проектирования. Эти элементы в текущей сборке **не используются**.

# 4. Электрическая распиновка ESP32-S3

Эта таблица **только для ESP32-S3**. Классическая ESP32 имеет другую карту пинов. Номера — GPIO SoC, не номера физических контактов на гребёнке; сверяй шелкографию платы.

| Узел / контакт | GPIO | Проверка |
|---|---:|---|
| TFT SCK + SD SCK | 12 | Общая SPI-шина |
| TFT SDA/MOSI + SD MOSI | 11 | Общая SPI-шина |
| SD MISO | 13 | Если слот на плате TFT, сверить его разводку |
| TFT CS | 10 | HIGH в покое |
| TFT DC/A0 | 39 | Data/Command |
| **TFT RESET** | **47** | Обязательный отдельный провод |
| SD CS | 14 | Не объединять с TFT CS |
| PCM5102A BCK | 16 | I²S BCLK |
| PCM5102A LCK/WS | 17 | I²S LRCK |
| PCM5102A DIN | 18 | I²S DATA |
| 5 кнопок (резистивная лестница) | 9 | ADC1, 10 кОм к 3,3 В по схеме |
| Аккумулятор через 100k/100k | 4 | ADC1, фильтр 100 нФ |
| HOLD | 21 | Внешний pull-up 10 кОм, переключатель на GND |
| Touch Wheel (6 секторов) | 1, 2, 5, 6, 7, 8 | Калибровать `touchRead()` |
| Звуковая пьеза | 42 | GPIO → высокоомная пьеза → GND |
| Нативный USB D− / D+ | **19 / 20** | Уже подключены к USB-C DevKit |

**GPIO41 не является входом синхронизации.** Старый `iAP1 RX` был экспериментальным UART-приёмником команд от 30-pin аксессуаров — он **удалён** из текущей прошивки и схемы. Синхронизация идёт через аппаратный USB ESP32-S3 без дополнительных GPIO-проводов. GPIO40/41 остаются свободными.

Встроенный RGB-светодиод (на ревизиях встречается GPIO38/48) прошивкой не используется. GPIO35–37 могут обслуживать OPI PSRAM; GPIO43/44 — штатный UART0/USB-UART-мост. Не занимать эти пины периферией без проверки схемы платы.

# 5. Логика USB-C на плате с двумя разъёмами

На типовой ESP32-S3 DevKit один Type-C соединён с нативным интерфейсом **USB Serial/JTAG или USB OTG** SoC на GPIO19/GPIO20; другой может быть соединён с отдельным USB-UART-конвертером на UART0. **Названия разъёмов зависят от ревизии.** Определи нативный порт по шелкографии, схеме или устройству в диспетчере устройств.

- **Нативный USB-C:** для `MonoPod USB Sync v1` (USB CDC, виртуальный COM-порт).
- **USB-UART-порт:** отладочные сообщения `Serial0` на 115200 бод; также может использоваться для прошивки.
- **USB-C на модуле TP4056:** исключительно для зарядки батареи в выключенном состоянии плеера.

Во время синхронизации использовать штатное питание DevKit от USB при выключенном батарейном DC/DC и отключённой зарядке TP4056. Не соединять выход аккумуляторного DC/DC 3,3 В и питание от USB без проверенной развязки. Не открывать нативный COM одновременно в Studio и Serial Monitor.

# 6. Прошивка и конфигурация

1. Установить Arduino IDE 2.x и пакет **ESP32 by Espressif Systems 3.x**.
2. Выбрать `ESP32S3 Dev Module`; `Flash Size: 16MB`; `PSRAM: OPI PSRAM` для N16R8; `USB Mode: Hardware CDC and JTAG`; `USB CDC On Boot: Enabled`; `Upload Mode: UART0 / Hardware CDC` (название зависит от Arduino core).
3. Поставить библиотеки **Adafruit GFX**, **Adafruit ST7735 and ST7789**, **ESP8266Audio**. Для S3 **не требуется ESP32-A2DP и не требуется Adafruit DRV2605**.
4. Открыть `DIY_iPod_Mono/DIY_iPod_Mono.ino`. В `Config.h` проверить выбор `MONOPOD_BOARD_ESP32_S3`, `FEATURE_USB_SYNC`, `CLICKER_HARDWARE=CLICKER_HW_PIEZO`, `MAX_TRACKS=2048`.
5. Запустить **Verify/Compile**, затем прошить. Первый запуск делать с отключённой периферией и аккумулятором. Учитывать, что без microSD логи покажут ошибку SD.
6. Для диагностики открыть USB-UART/`Serial0` 115200. Нативный USB CDC предназначен **только для протокола MonoPod**, текстовый монитор там занимать не должен.
7. Подключить дисплей и microSD, затем PCM5102A, проверить аналоговую часть и кнопки/колесо. USB transfer включать после успешной инициализации карты.

В S3 сборке A2DP/AVRCP исключаются **на этапе препроцессора**; пункта Bluetooth нет в Settings. В классической ESP32 можно использовать A2DP экспериментально, но нативный USB Sync v1 в этом профиле выключен.

# 7. USB Sync v1 — протокол, операции и ограничения

В v0.8.3 реализован **собственный USB CDC протокол**, а не USB Mass Storage, не Apple iAP и **не синхронизация с iTunes**. Это рациональный способ передавать аудиофайлы на microSD с ПК через уже имеющийся нативный USB без выделения UART GPIO.

Передача через `UsbSync.cpp`: `Serial` на нативном USB зарезервирован под обмен, диагностические сообщения выводятся только через `Serial0`.

| Запрос от ПК (строка с LF) | Ответ устройства | Назначение |
|---|---|---|
| `MPOD1 HELLO` | `MPOD1 READY 1 SD=1` | Обнаружение устройства/версии |
| `MPOD1 INFO` | `MPOD1 OK INFO SD=1 TRACKS=N` | Состояние карты и индекс |
| `MPOD1 PUT <SIZE> <CRC32HEX> <FILENAME>` | `MPOD1 NEXT N` | Начало загрузки файла |
| Бинарные `N` байт | `MPOD1 NEXT N` или `MPOD1 OK SAVED` | Передача блоками до 1024 байт, обратное управление потоком |
| `MPOD1 SCAN` | `MPOD1 OK SCANNED N` | Пересканирование `/Music` после серии загрузок |

Файл сохраняется во временный `/Music/.monopod-upload.part`. После сверки CRC32 он переименовывается в `/Music/<имя>`. При ошибке, обрыве или 15-секундном тайм-ауте временный файл удаляется; существующие файлы не перезаписываются. Имена проверяются, `../` и разделители пути отклоняются. Доступны `.mp3`, `.wav`, `.flac`, `.aac`, размер одного файла — до 256 МиБ.

Прототип **не поддерживает** удаление, двустороннюю синхронизацию метаданных, плейлистов iTunes, Apple USB identification или iPod database; это будущие отдельные задачи. Во время USB PUT нельзя запускать Wi-Fi Sync, извлекать карту или использовать её как USB Mass Storage.

## 7.1. Передача с компьютера

В терминале Windows/macOS/Linux из директории проекта:

```bash
python -m pip install -r Studio/requirements.txt
python Studio/usb_sync.py ports
python Studio/usb_sync.py --port COM7 info
python Studio/usb_sync.py --port COM7 send "Track 01.mp3" "Track 02.flac"
```

На Linux заменить `COM7` на `/dev/ttyACM0` (или обнаруженное имя). В **MonoPod Studio → Device & Music** выбрать USB CDC port, нажать **USB Connect / Refresh**, затем **Upload over USB-C**. При недоступности нативного USB проверить `USB CDC On Boot`, выбранный порт и занятость порта Serial Monitor.

# 8. Схема аккумуляторного питания (TP4056)

```text
USB 5 В зарядника ──> TP4056 IN+/IN−
                         │
Li-ion/Li-Po 1S ──> TP4056 B+/B−
                         │
TP4056 OUT+/OUT− (только модуль с защитой)
          │
     Выключатель +/−
          │
  Buck-boost DC/DC 3,3 В ──> системная 3V3/GND
```

**Внимание:** не все TP4056-модули имеют защиту и клеммы OUT+/OUT−. На двухконтактном модуле выход нагрузки и защита решаются отдельно. TP4056 не содержит полноценного power-path: для прототипа зарядка **только при выключенном плеере**. Сравнить маркировку RPROG с даташитом и допустимым зарядным током аккумулятора; типичные платы на 1 А могут быть слишком агрессивными для конкретного элемента.

**Не подавать 4,2 В Li-ion прямо на 3V3 ESP32.** Перед первым подключением проверить на холостом ходу и под нагрузкой DC/DC выход 3,3 В, пульсации/пусковые выбросы, температуру и отсутствие backfeed в USB. Сначала работает стенд от USB DevKit **без аккумулятора**, затем отдельное питание Rev. A-P. USB на плате ESP32-S3 **не заменяет** TP4056.

# 9. Отладка аудио PCM5102A → TDA1308

1. Проверить земли и питание обеих плат. PCM5102A выдаёт **линейный сигнал**, TDA1308 требует правильных условий питания/входного смещения именно для используемого модуля.
2. На отключённых наушниках измерить мультиметром постоянную составляющую выходов L/R ЦАП и усилителя относительно GND. Нельзя ориентироваться только на размах AC.
3. С подачей тестового синуса 500 Гц и 1/5/10/20 кГц сравнить осциллограммы **на линейном выходе PCM5102A**, **на входе усилителя** и **на выходе TDA1308**. Начать с малого уровня.
4. Сверить рабочую точку входов, цепи разделительных конденсаторов, VREF/виртуальную землю и нагрузочную способность TDA1308 по его даташиту и **фактической схеме платы**.
5. Проверять выход сначала на эквиваленте 32 Ом подходящей мощности, затем на наушниках при безопасном уровне и проверенном отсутствии DC.

**Признак отказа:** PCM5102A синус без срезания, после TDA1308 появляются клиппинг/асимметрия → искать питание, смещение, перегрузку, неверное включение или дефект усилительного модуля. Не пытаться исправить это увеличением software gain.

# 10. Дисплей, microSD, колесо, звуковой clicker

**ST7735S:** RESET физически подключён к GPIO47 (в S3 не `-1`); TFT и SD имеют общую SPI-шину, но отдельные CS=10 и CS=14. Не путать 5-вольтовые и 3,3-вольтовые версии модулей. Проверять стабильность картинки после холодного старта и при чтении с SD.

**Медиатека:** в `Config.h` установлен предел **2048 треков**. Минимальная цель — **1024 реальных трека** на выбранной FAT32 microSD. Ресурсы String/ID3 зависят от размеров путей и доступной памяти; использовать логи `heap free`/`PSRAM free` после сканирования. Надпись о лимите не означает гарантию успешной индексации на неподтверждённой плате.

**Click Wheel:** шесть электродов на GPIO1,2,5,6,7,8. В S3 значение `touchRead()` при касании в данной реализации сравнивается как **увеличение над базой**. Проверять без пальца, с пальцем, при включённом дисплее/радио и на разных длинах проводов; тонко настраивать пороги и фильтрацию.

**Clicker:** пьезо на GPIO42 создаёт только **короткие звуковые импульсы**; он не моделирует механическую вибрацию. На текущем прототипе никакого haptic управления нет. Встроенный RGB выключен логически, его GPIO не используется.

# 11. Диагностика USB Sync и типовые ошибки

| Симптом | Проверка | Действие |
|---|---|---|
| В Studio нет COM-порта | Кабель, нативный USB-C, драйвер, меню USB CDC | Открыть `python Studio/usb_sync.py ports` |
| Нативный порт есть, нет `READY 1` | `USB CDC On Boot`, режим USB, прошивка, занятость COM | Закрыть Serial Monitor, перепрошить с правильным USB Mode |
| `ERR NO_SD` | microSD/CS/SPI/FAT32 | Проверить GPIO14, модуль карты, SD mount |
| `ERR WIFI_ACTIVE` | Одновременный HTTP upload | Остановить Wi-Fi Sync и повторить |
| `ERR INVALID_FILE` | Имя, расширение, размер | Использовать MP3/WAV/FLAC/AAC и короткое имя |
| `ERR ALREADY_EXISTS` | Файл на SD уже есть | Удалить/переименовать вручную на карте и повторить |
| `ERR CRC_MISMATCH` | Потеря/искажение данных, обрыв | Проверить USB-кабель/питание, повторить загрузку |
| `ERR TIMEOUT` | Передача остановилась на 15 с | Проверить устройство/питание и отсутствие второго клиента COM |
| Треки записаны, но не видны | Индекс устарел | Отправить `SCAN`, выполнить Rescan Music |
| В чипе нет 8 МБ PSRAM | неверный профиль/плата | Проверить маркировку модуля и настройки OPI PSRAM |
| Чёрный экран | RESET/DC/CS/SPI/питание | Проверить GPIO47/39/10/12/11 |
| Искажения после TDA1308 | DC/VREF/разделительные конденсаторы/нагрузка | Поэтапно сравнить синусы с осциллографом |

# 12. Протокол испытаний и критерии завершения Rev. A-P

- [ ] Сборка Arduino-ESP32 3.x для ESP32-S3 N16R8 с `FEATURE_USB_SYNC=1`, без Bluetooth Classic и библиотек A2DP/DRV2605.
- [ ] Загрузка на DevKit от штатного USB, **без аккумулятора**; 16 МБ Flash и PSRAM определены.
- [ ] TFT RESET на GPIO47 работает, SD отдельно инициализируется, графика не ломается при чтении с SD.
- [ ] 6 секторов Click Wheel, 5 кнопок, HOLD и звуковая пьеза корректно работают.
- [ ] PCM5102A выдаёт чистый аналоговый сигнал, TDA1308 не имеет опасного DC на выходе.
- [ ] Порт native USB CDC обнаружен ПК, `HELLO`/`INFO` возвращают ответы, тестовая аудиозапись передаётся без ошибки CRC.
- [ ] Обрыв USB посреди записи не оставляет трек в `/Music`, `SCAN` обновляет медиатеку.
- [ ] На карте с минимум 1024 треками индекс не повреждается, UI остаётся отзывчивым.
- [ ] TP4056, защита, DC/DC, выключение и зарядка при выключенном плеере проверены мультиметром/осциллографом.
- [ ] Работа от аккумулятора подтверждена после проверки развязки; температура узлов и качество звука нормальные.

# 13. Будущее развитие Rev. B

План максимум: собственная PCB с интегрированными зарядкой, стабилизацией, ESD, экраном, наушниковым усилителем и сенсорным колесом. Возможны **BQ24074 с power-path вместо отдельного TP4056** и **DRV2605L/LRA вместо пьезы**, но это самостоятельная ревизия, **в текущей BOM они отсутствуют**. Полноценные iTunes/iPod database, Apple iAP over USB, USB Mass Storage со строгой синхронизацией файловой системы и двусторонний менеджер медиатеки не реализованы и потребуют отдельного проекта.

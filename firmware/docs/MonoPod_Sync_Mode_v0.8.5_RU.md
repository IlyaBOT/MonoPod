# MonoPod v0.8.5 — USB/Wi-Fi Sync Mode: реализация и проверка

## Режимы

- `Idle` — обычное воспроизведение и управление, USB CDC подключён/виден но это НЕ синхронизация; подключение к обычной Wi-Fi сети — тоже не синхронизация.
- `UsbCdc` — **только MonoPod Studio**, собственный протокол MPOD1 поверх нативного USB-C ESP32-S3. Вход по `MPOD1 SYNC START` из Studio; `HELLO` / `INFO` не переключают режим. Эксклюзивная загрузка, удаление, `SCAN`; выход после последней транзакции по `MPOD1 SYNC END`, пересканирование библиотеки.
- `WiFi` — включается вручную `Settings > Wi-Fi > Start Wi-Fi Sync`; запускает локальную точку доступа MonoPod, HTTP сервер для Studio. Не включается от подключения Wi-Fi или открытия настроек. Выход: **удержание Select 1.5 секунды**, только если нет активной загрузки. После выхода сканирование библиотеки.
- `UsbMsc` — зарезервированное состояние для будущего настоящего USB Mass Storage / iTunes. В v0.8.5 **не активируется**, отдельный MSC-Lab остаётся прототипом и не интегрирован в основную прошивку. Простой COM-порт — не iPod.

## Блокировка

Вызов `SyncController::enter`: проверка microSD → `player.stop()` с закрытием аудиофайла → `feedback.quiet()` → смена владельца Sync → отдельный экран. В `loop()` декодер не обслуживается в режиме Sync. UI игнорирует все кнопки и wheel, кроме намеренного SelectLong в Wi-Fi idle. Автоматическое гашение подсветки и sleep timer приостановлены; обычные меню и операции удаления недоступны. Wi-Fi сканер в UI приостанавливается на весь Sync.

## Экран 160×128

- USB: крупная пиктограмма USB над **SYNC**.
- Wi-Fi: крупная пиктограмма сети над **SYNC**.
- Постоянное предупреждение: `DO NOT REMOVE SD` + `DO NOT UNPLUG USB` или `KEEP Wi-Fi CONNECTED`.
- Во время активного HTTP / MPOD1 передачи: `DATA TRANSFER ACTIVE`.
- Нет обычной верхней панели/списков, нет приёма play/pause / next / back. Текст использует пиксельную графику и палитру MonoPod, поддерживает Wokwi.

## USB PC protocol v3 (дополнение к MPOD1 v2)

```
HOST  MPOD1 HELLO                  -> MPOD1 READY 3 SD=1|0
HOST  MPOD1 INFO                   -> MPOD1 OK INFO SD=... TRACKS=... TOTAL_BYTES=... FREE_BYTES=... GUID=...
HOST  MPOD1 SYNC START             -> MPOD1 OK SYNC_STARTED | ERR NO_SD | ERR SYNC_BUSY
HOST  MPOD1 PUT / REPLACE / DELETE / SCAN -> только после START; вне сеанса ERR SYNC_REQUIRED
HOST  MPOD1 SYNC END               -> MPOD1 OK SYNC_ENDED | ERR NO_USB_SYNC | ERR TRANSFER_ACTIVE
```

Стандартные операции `Upload/Update`, `Delete` и `SCAN` в Studio сами запускают сеанс при первом изменении и завершают при закрытии клиентского контекста. Кнопка `USB Connect / Refresh` вызывает только `HELLO/INFO`, не трогает аудио. При обрыве посреди бинарного потока не нужно отправлять текстовую команду посреди незавершённого пакета: устройство сбрасывает неполный временный файл по таймауту (15 секунд), режим Sync остаётся до повторного безопасного окончания сеанса. Восстановление и безопасное завершение после внезапной потери CDC требуют аппаратной проверки.

## Защита карты

- Wi-Fi HTTP временный `/Music/.monopod-wifi.part`, затем атомарная по операциям ФС замена файла; при замене прежний трек временно `.monopod-wifi.bak`, имя старого файла фиксируется `.monopod-wifi.target` для восстановления после перезагрузки.
- USB CDC CRC32, временный файл `.monopod-upload.part` с журналом/backup существующего файла из v0.8.4.
- Wi-Fi и USB взаимно исключаются через `SyncController`. Внутри обеих реализаций `busy` препятствует выходу во время загрузки; **при отключении питания/извлечении microSD во время записи FAT32 всё равно может повредиться**.
- Для будущего `UsbMsc`: нельзя одновременно смонтировать microSD локально через Arduino SD и экспортировать её ПК на запись. Нужно полностью отдать эксклюзивное владение, отмонтировать карту на MCU и вернуть после подтверждённого eject/flush.

## Отличия от оригинального iPod 3G

Исторический iPod 3G (A1040, 2003) мог **автоматически** начать iTunes Auto-Sync при подключении; экран показывал `Do not disconnect` и запрещал обычное использование до безопасного отключения/извлечения. MonoPod сознательно требует **явного входа в режим**. Изображение MonoPod `USB/Wi-Fi + SYNC` — собственный интерфейс, не побайтовая копия ROM-экрана Apple. Ни VID/PID, ни USB MSC, ни разбор `iTunesDB` для iTunes в основной прошивке ещё не проверены. Для исследования см. `CODEX_TASK_iPod3G_USB_iTunes_Reverse_Engineering_RU.md`.

## Проверки

1. ПК подключает USB-C, открывает Studio INFO: музыка не останавливается, режим Sync не включается.
2. Studio Upload → `SYNC START`: аудио закрывается, появляются USB и крупный SYNC; кнопки не меняют трек.
3. Загрузка CRC32 и успешный `SYNC END`: библиотека обновляется, возвращается меню.
4. Без microSD команды `SYNC START`, `PUT` получают ошибку, UI показывает `No microSD card`.
5. Wi-Fi в обычном состоянии не выключает музыку. `Start Wi-Fi Sync` → воспроизведение останавливается, Wi-Fi SYNC, меню недоступно. Нажатие Play/Pause ничего не делает.
6. Во время HTTP POST удержание Select не должно выключить AP; в idle удержание Select 1.5s завершает сеанс.
7. Проверить обрыв USB во время `PUT`, восстановление после reset, отслеживание состояния `busy`, правильное восстановление `.bak/.target` на expendable FAT32 microSD.

**Состояние проверки:** Python host/mock/source tests пройдены; полная сборка Arduino-ESP32, реальный ESP32-S3/USB CDC/HTTP тест и iTunes не проверялись в данной среде. Остающиеся риски: скорость ESP32-S3 USB OTG Full-Speed 12 Mbit/s, надёжность power-loss на FAT32, необходимость аппаратного теста переходов в Sync, запрет на горячую замену microSD во время записи.

# MonoPod v0.8.7 — UART-консоль управления (ESP32-S3 N16R8)

## Назначение

Для периода, пока нет физического Click Wheel и кнопочной платы, можно полноценно перемещаться по меню через **UART0**. Это режим **во время работы прошивки**, а не `#define`: ввод `$DISABLE_HARDWARE_CONTROL=1` мгновенно исключает `input.poll()` из рабочего цикла. При этом перестают опрашиваться вход HOLD, резистивная кнопочная лестница, ёмкостное колесо и экспериментальный энкодер. Экран, аудио, microSD, Wi-Fi и MonoPod Studio продолжают работать.

Выбранное состояние не записывается в NVS. После перезапуска аппаратное управление снова включено; при необходимости повторите команду. Для команд использован только диагностический UART, чтобы исключить случайное вмешательство в бинарный транспорт MonoPod Studio.

## Подключение

- **ESP32-S3 N16R8 с двумя Type-C:** диагностическая консоль — `Serial0` / UART0, обычно второй USB-C через USB-to-UART мост (зависит от ревизии платы). **115200 бод, 8N1, окончание строки `Newline` либо `Both NL & CR`.**
- Нативный USB ESP32-S3 (`Serial`, GPIO19/20) зарезервирован под `MPOD1` USB Sync. **Нельзя** отправлять эти `$...` команды в тот COM-порт, который открывает MonoPod Studio: они не часть протокола `MPOD1`.
- Если не используется USB-to-UART мост, UART0 обычно выведен как TX GPIO43, RX GPIO44; подключать внешний USB-UART только с общей GND и логическими уровнями 3,3 В. Не соединять два питания VBUS и не подключать к пинам UART 5 В.
- На классическом ESP32 или в Wokwi, когда `FEATURE_USB_SYNC=0`, консоль использует `Serial`.

## Команды (вводятся целиком, с `$`)

| Команда | Назначение |
|---|---|
| `$DISABLE_HARDWARE_CONTROL=1` | Отключить опрос всех аппаратных органов управления, включая HOLD |
| `$DISABLE_HARDWARE_CONTROL=0` | Снова включить аппаратные кнопки и колесо |
| `$MENU` | Кнопка Menu / назад |
| `$SELECT` | Короткое Select |
| `$SELECT_LONG` | Длительное Select (для подтверждений и штатного выхода из Wi-Fi Sync, когда передача завершена) |
| `$UP`, `$DOWN` | Одно деление виртуального колеса |
| `$SCROLL=DOWN,5`, `$SCROLL=UP,5` | Последовательность до 32 делений, без блокирующей задержки |
| `$PREV`, `$NEXT` | Предыдущий/следующий трек или навигация |
| `$PLAY` | Play/Pause |
| `$KEY=MENU` | Альтернативный синтаксис; работают также `SELECT`, `SELECT_LONG`, `UP`, `DOWN`, `PREV`, `NEXT`, `PLAY_PAUSE` |
| `$STATUS` | Состояние аппаратного управления, Sync и очереди |
| `$BATTERY` | Сырое измерение GPIO4 в мВ, рассчитанное напряжение и приблизительный процент |
| `$SD` | Смонтирована ли карта, число треков и текст ошибки |
| `$HELP` | Список команд |

Ответы имеют префикс `[DEV]`, например: `[DEV] OK HARDWARE_CONTROL=DISABLED (runtime only)`.

### Пример запуска

```text
$DISABLE_HARDWARE_CONTROL=1
[DEV] OK HARDWARE_CONTROL=DISABLED (runtime only)
$STATUS
[DEV] HARDWARE_CONTROL=DISABLED SYNC=NONE QUEUED=0
$SELECT
[DEV] OK KEY_QUEUED=1
$SCROLL=DOWN,5
[DEV] OK KEY_QUEUED=5
$BATTERY
[DEV] BAT_ADC=1970 mV VBAT=3.940 V PERCENT=... GPIO=4
```

При погасшем дисплее первое виртуальное нажатие лишь будит подсветку, как обычная кнопка. Чтобы экспериментальная проверка не была заблокирована случайным низким уровнем GPIO21, во время принудительного отключения hardware-control проверка HOLD в UI также пропускается.

## Безопасность Sync Mode

- В обычном режиме можно отправлять любые виртуальные кнопки.
- При активном USB или Wi-Fi Sync обычные команды навигации отклоняются с `[DEV] ERR SYNC_LOCKED`.
- Для Wi-Fi Sync команда `$SELECT_LONG` допускается только по предусмотренным ранее правилам UI: если передача не идёт, Wi-Fi сеанс можно безопасно завершить.
- USB Sync по-прежнему завершается **только командой Studio `MPOD1 SYNC END`**, не через UART-консоль. USB-подключение само по себе Sync Mode не запускает.

## Ограничения и тестирование

Код консоли находится в `DevConsole.cpp/.h`, разбор команд — в `DevConsoleProtocol.h`. Вход ограничен 95 ASCII-символами на строку, прокрутка — 32 шагами за команду, с интервалом не менее 45 мс между шагами. Чтение неблокирующее, бюджет 64 байта за итерацию `loop()`. При выключении/включении hardware-control сбрасывается состояние антидребезга кнопок; повторного входа в режим загрузки ESP32 не требуется.

Парсер протестирован отдельным нативным C++ тестом, проверена интеграция с обоими профилями проекта. **Полная сборка Arduino на железе и аппаратные испытания ещё не выполнялись.**

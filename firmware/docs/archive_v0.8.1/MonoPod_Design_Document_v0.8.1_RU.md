# 1. Назначение и статус

**MonoPod** — компактный DIY музыкальный плеер на оригинальном **ESP32-WROVER (с PSRAM)**, вдохновлённый UX монохромного iPod 4-го поколения. Интерфейс работает на доступном цветном **ST7735S 1,8″** в режиме палитры из четырёх оттенков и разрешении **160×128** (поворот физического 128×160). Музыка хранится на microSD; проводной звук идёт через PCM5102A и усилитель TDA1308; Bluetooth Classic A2DP Source и AVRCP — экспериментальный путь v0.8-rc.

**Назначение документа:** дать единую последовательность действий от безопасного настольного макета до автономного корпуса, с распиновкой, режимами сборки, контрольными точками, командами, типовыми отказами и критерием сдачи. Это проектная спецификация, **не сертификат готовности или протокол уже проведённых испытаний**.

# 2. Ревизии и границы проекта

**Rev. A — настольный этап отладки:** ESP32-WROVER на штатном USB-питании, дисплей, microSD, USB-UART, кнопки, сенсорное колесо, PCM5102A и *проверенный на нагрузке* усилитель наушников. Модули соединяются короткими проводами; аккумулятор пока отсоединён, пока не проверена силовая схема.

**Rev. A-P — макет от аккумулятора (текущий выбранный вариант):** Li-Po 1S 1000 мА·ч, **готовый модуль TP4056**, проверенная защита аккумулятора, выключатель нагрузки и отдельный стабилизированный источник 3,3 В для ESP32. **Зарядка — при выключенном плеере**; USB зарядника и USB-UART DevKit пока раздельные. Схема Rev. A-P ниже — руководство по соединениям при условии проверки фактической платы и способа подачи 3,3 В на DevKit. **BQ24074 здесь не применяется.**

**Rev. B — компактная собственная PCB и корпус (план максимум):** обмер модулей, интегрированные аудио/питание, профилированное колесо, ESD и тепловые испытания; **возможна замена TP4056 на BQ24074 с power-path**, но только после отдельного проектирования и проверки.

Не следует одновременно менять плату питания, аналоговый усилитель и алгоритмы Bluetooth: при отказе потеряется возможность локализовать причину.

# 4. Единая распиновка — фактический `Config.h` v0.8.1

| ESP32 GPIO | Сигнал | Подключение / ограничения |
|--:|:--|:--|
| **18** | SPI SCK | TFT SCK + SD SCK, общая шина |
| **23** | SPI MOSI | TFT SDA/MOSI + SD MOSI |
| **19** | SPI MISO | SD MISO; TFT MISO обычно не нужен |
| **5** | TFT CS | Активный LOW; strapping GPIO — проверять boot |
| **22** | TFT D/C (A0) | Data/Command |
| **−1** | TFT RESET в Config | Это не GPIO; ST7735 `RST` подключить к `EN` ESP32 / общей линии сброса, либо выделить безопасный GPIO и изменить `Config.h` |
| **21** | SD CS | Отдельный CS, не объединять с TFT CS |
| **26** | I²S BCLK | PCM5102A `BCLK/BCK` |
| **25** | I²S LRCK/WS | PCM5102A `LR/LCK` **цифровой вход** |
| **15** | I²S DATA | PCM5102A `SD/DIN`; strapping GPIO |
| **4, 13, 14, 27, 33, 32** | Click Wheel x6 | TOUCH0/4/6/7/8/9, в порядке обхода |
| **34** | 5-кнопочная лестница | Только вход, 10 кОм к 3,3 В |
| **35** | HOLD | Только вход; внешний 10 кОм к 3,3 В, переключатель к GND |
| **2** | Piezo | Пассивная высокоомная пьеза, strapping GPIO |
| **36** | BAT ADC | 100k верх + 100k низ, 100 нФ на GND |
| **1 / 3** | UART0 TX/RX | USB-UART, Serial 115200 |
| **39** | Резерв/iAP1 RX | Экспериментальная функция **выключена** |

**Резервы/конфликты.** GPIO6–11 заняты Flash; GPIO16/17 у WROVER могут быть заняты PSRAM. GPIO34–39 являются только входами без внутренних подтяжек. GPIO0/2/5/12/15 определяют загрузочные состояния: периферия на них не должна создавать неправильный уровень при сбросе. Режим DRV2605L использует GPIO32/33 как SDA/SCL и **сокращает кольцо до 4 секторов**. Dev encoder на 36/39 конфликтует с аккумулятором; `FEATURE_DEV_ENCODER=0`.

**Важное ограничение платформы:** ESP32-WROVER умеет Bluetooth Classic и A2DP, а ESP32-S3/C3 для Classic A2DP в данном проекте не заменяют его напрямую. USB на текущей DevKit — USB-UART, а не аппаратный USB Device для iTunes/MSC.

## 4.1. TFT + microSD: общий SPI

```text
ESP32 GPIO18  ───── TFT SCK, SD_SCK
ESP32 GPIO23  ───── TFT SDA(MOSI), SD_MOSI
ESP32 GPIO19  ───── SD_MISO
ESP32 GPIO5   ───── TFT_CS
ESP32 GPIO22  ───── TFT_DC (A0)
ESP32 GPIO21  ───── SD_CS
ESP32 GND     ───── TFT GND, SD GND
ESP32 3V3     ───── питание модулей, если разрешено их схемой
```

До включения измерить сопротивление питания TFT ↔ GND, выяснить, есть ли на модуле штатный LDO/логические делители, есть ли отдельный вывод LED и куда он подключен. Для первой проверки не превышать SPI частоту из `Config::SPI_SD_HZ = 10 000 000` для SD. Оба CS должны быть HIGH, когда устройство не выбрано. Если экран работает, а SD нет — начать с CS, затем MISO и питания; не увеличивать сразу SPI speed.

## 4.2. Кнопки — ADC ladder на GPIO34

```text
 3V3 ──[10k pull-up]──┬──────── GPIO34
                     ├── MENU   ──[0 Ω]───── GND
                     ├── PREV   ──[2.2k]──── GND
                     ├── NEXT   ──[4.7k]──── GND
                     ├── PLAY   ──[10k]───── GND
                     └── SELECT ──[22k]───── GND
```

При одиночном нажатии ожидаются приблизительно **0 / 0,59 / 1,06 / 1,65 / 2,27 В**; без нажатия ~3,3 В. Фактические окна в `Input.cpp`, в милливольтах: MENU ниже 200; PREV 350–820; NEXT 870–1290; PLAY 1440–1840; SELECT 2010–2580. Неподтверждённые окна требуют калибровки по `analogReadMilliVolts(34)`, особенно на реальном делителе. Одновременные кнопки в этой схеме не поддерживаются.

**Select:** v0.8-rc генерирует короткий `Select` **после отпускания** (после фильтра дебаунса ~35 мс). Удержание не менее **1500 мс** генерирует `SelectLong` один раз; последующее отпускание не должно выдавать второй обычный Select. Для остальных кнопок реакция остаётся по нажатию; Prev/Next имеют повтор при длительном удержании.

## 4.3. Сенсорное колесо Click Wheel

Шесть отдельных медных электродов по окружности; ориентир внешнего диаметра кольца **48 мм**, внутреннего **25 мм**, зазор **1–2 мм**, накладка-диэлектрик **0,5–1 мм**. Электроды изолировать друг от друга, не размещать под ними сплошной полигон GND. Последовательно подключать TOUCH GPIO в том же обходе, который установлен в `Config::WHEEL_PINS`. Не вести провода рядом с BCLK, SPI CLK и антенной ESP32.

Алгоритм `Input.cpp`: baseline 32 измерения без касания после boot; дальше проверка изменения `touchRead()`, вычисление `atan2()` и накопление углового шага 0,40 рад. Программные пороги и гистерезис требуют реального теста. Диагностировать через таблицу `touchRead(pin)` без руки/с рукой, затем индивидуально подбирать threshold. **На момент включения руки на колесе быть не должно** — иначе baseline будет ошибочным.

# 5. Аудиотракт: PCM5102A → TDA1308 → 3,5 мм

## 5.1. Разводка I²S

| PCM5102A Audio DAC v2 | Куда подключить |
|:--|:--|
| `3V3` | Стабильные 3,3 В согласно схеме именно этого модуля |
| `GND` (digital) | Общая земля с ESP32 |
| `BCLK` | GPIO26 |
| `LR` / `LRCK` | GPIO25 (I²S Word Select, **не** левый аудиовыход) |
| `SD` / `DIN` | GPIO15 |
| `MCLK / SCK` | В 3-проводном режиме **не генерируется**; обвязка зависит от конкретного модуля, проверить по PCB/datasheet |
| `L`, `R` (analog) | Входы L/R усилителя через его входные разделительные цепи |
| `GND` (analog) | Общая низкошумящая земля аналогового тракта |

PCM5102A — **линейный DAC**, его выход не рассчитан на штатную прямую нагрузку 32 Ом. Факт, что Marshall Major IV играли напрямую, не является подтверждением безопасного финального режима. Не использовать динамик 4 Ом для проверки этого линейного выхода.

## 5.2. Последовательность измерений, без риска для наушников

1. Отключить TDA1308 и все наушники; проверить 3,3 В DAC без просадок и общий GND.
2. Подать цифровой синус **1 кГц / 44,1 кГц stereo** с регулируемым PCM gain, убедиться в исправных BCLK, LRCK, DIN и отсутствии ошибок частоты. В режиме I²S 44,1 кГц на ESP32 BCLK определяется разрядностью слота: например **1,4112 МГц при 2×16 бит** или **2,8224 МГц при 2×32 бит**; реальную slot width взять из работающего драйвера, не угадывать по осциллограмме.
3. Замерить синус по отдельности на L/R DAC относительно GND при нагрузке **10 кОм**. Измерить DC мультиметром при паузе/нулевом PCM; проверить отсутствие клиппинга на средних и пиковых уровнях.
4. Повторить на **500 Гц, 1, 5, 10, 20 кГц** при 44,1 кГц sample rate. Для 20 кГц осциллограф покажет форму, зависящую от фильтра и близости к Найквисту; «идеальная синусоида» в каждой точке не является обязательным критерием.
5. Подать источник известной формы на **вход TDA1308** через разрешённую входную цепь/аттенюатор. Сначала измерять **без наушников**, затем на эквиваленте **32 Ом**, и только после прохождения DC/тепловых тестов — на реальных наушниках.
6. На каждой стадии сохранить: режим, частоту, gain, VDD, DC на входе/выходе, Vpp и тип нагрузки. Осциллограф использовать в DC coupling для смещения, в AC coupling — для оценки малой амплитуды.

## 5.3. Усилитель TDA1308: открытая неисправность

Имеющийся красный модуль TDA1308 (~20×20×3 мм) давал сильные искажения на наушниках при очень малом `gain`, хотя один пассивный динамик JVC 4 Ом субъективно играл. Это **не доказательство** исправности: 4 Ом для такого усилителя — нештатная нагрузка. Измеренные ранее DC 1,2/1,5 В на входах и 0,115/0,521 В на выходах сделаны без полной фиксации схемы/нагрузки и не являются готовым диагнозом.

План собственного варианта TDA1308: схема по datasheet NXP, входные AC-конденсаторы с корректным VREF, локальный 100 нФ и электролит на питание, **выходные 220–470 мкФ на канал** для одно-полярной схемы (если нет встроенной/внешней DC-free топологии), осмысленная отрицательная обратная связь, ограничение уровня на входе, площадки GND/VREF/IN/OUT/3V3. Для 32 Ом 220 мкФ даёт нижний полюс примерно **22,6 Гц**, 470 мкФ — **10,6 Гц**. **Никаких наушников, пока DC на джеке и выходная амплитуда не проверены.**

Приоритет поиска неисправности: DC смещение/неподходящая выходная развязка → ошибочная обвязка TDA1308 → земля/питание/помехи → неверный TRS pinout → повреждение микросхемы. Тестировать оба канала независимо.

# 6. Аккумулятор, зарядка и системное питание Rev. A-P: TP4056

**Выбранное решение:** готовая плата **TP4056**, защищённый Li-ion/Li-Po **1S 3,7 В, 1000 мА·ч**, выключатель плеера и отдельный **buck-boost 3,3 В**. Это модульный прототип, а не новая PCB; фактические маркировки платы имеют приоритет над типовой картинкой. Питание и зарядка ниже **не проходили проверку на реальном MonoPod**.

## 6.1. Подключение TP4056 и переключателя

Для платы **с защитой** (обычно контакты `B+`, `B−`, `OUT+`, `OUT−`; наличие DW01A/FS8205A или аналогов подтвердить по деталям платы):

```text
ЗАРЯДКА (плеер ВЫКЛЮЧЕН, USB-UART DevKit отключён):
Отдельный USB 5 В ──────> TP4056 USB / IN+ / IN−
                              TP4056 B+  ───────> Аккумулятор 1S +
                              TP4056 B−  ───────> Аккумулятор 1S −

ПИТАНИЕ ПЛЕЕРА ОТ АККУМУЛЯТОРА (зарядный USB отсоединён):
TP4056 OUT+ ──[выключатель]──> IN+ buck-boost 3,3 В
TP4056 OUT− ─────────────────> IN− buck-boost 3,3 В
                                   OUT+ (3,3 В) ──> System 3V3*
                                   OUT−         ──> System GND

* System 3V3 / питание DevKit: только после проверки схемы
  штатного LDO, USB-питания и отсутствия обратного тока.
```

**Проверить тип платы перед монтажом:** если на модуле только `B+`/`B−` и нет выходов `OUT±`, **не считать его защищённым**. Использовать аккумулятор со штатной защитой либо отдельную защитную плату, рассчитанную на пиковый ток плеера. На типовой плате с защитой `OUT+` может быть соединён с `B+`, а отключение по защите выполняется по минусу: **не обходить `OUT−` прямым соединением с `B−`**. Не путать B-клеммы аккумулятора и OUT-клеммы нагрузки.

**Почему не напрямую:** TP4056 — только линейное CC/CV-зарядное для 1S (до 4,2 В), **не регулятор 3,3 В и не power-path**. Аккумулятор может иметь напряжение около 3,0–4,2 В; прямое соединение с пином `3V3` рискованно, с `5V/VIN` — обычно не обеспечит нормальную работу. AP2112K-3.3 также не гарантирует стабилизированные 3,3 В на разряжающемся 1S, поэтому для Rev. A-P выбран buck-boost с проверенными напряжением, пиковым током и уровнем помех I²S/аналогового тракта.

**Раздельные USB на текущем макете:** вход USB модуля TP4056 используется только для зарядки; штатный USB DevKit — только для прошивки/Serial при **разомкнутом выключателе батарейного питания**. Не соединять без проекта развязки два источника 5 В и не включать батарейный стабилизатор одновременно со штатным USB DevKit. Для программирования безопаснее отключать батарейный источник полностью; для автономного теста — отключать USB DevKit. Объединение в один USB-C требует отдельного узла питания и проверки обратных токов, в Rev. A-P не реализуется.

## 6.2. Ток зарядки, защита и тепловые ограничения

TP4056 задаёт ток зарядки резистором `RPROG`. По даташиту при 5 В типовые значения: **1,2 кОм → 1 А**, **2,4 кОм → 0,5 А**, **3,0 кОм → 0,4 А**. Для начальных испытаний аккумулятора 1000 мА·ч консервативный ориентир — **около 0,5 А (2,4 кОм)**, **если паспорт именно этого аккумулятора разрешает такой ток**. Некоторые готовые платы имеют 1,2 кОм/1 А по умолчанию: проверить маркировку/измерить сопротивление резистора `PROG`, а не считать ток известным. Под нагрузкой и при нагреве ток может снижаться из-за терморегуляции самого чипа.

Защита от **перезаряда/переразряда/КЗ/перегрузки** должна быть в аккумуляторной сборке либо отдельной плате защиты. **TP4056 сам по себе не заменяет защиту аккумулятора.** На многих готовых модулях `TEMP` подключён без внешнего термистора; наличие температурного контроля аккумулятора **не предполагать**. Во время первых зарядок контролировать нагрев платы и аккумулятора, не закрывать их корпусом, не заряжать повреждённый или вздутый элемент.

В обычном TP4056 завершение заряда определяется спадом тока приблизительно до **1/10 заданного**. Если плеер параллельно потребляет ток с выходов батареи, заряд может неправильно завершаться, продолжаться дольше или не завершиться вообще. **Правило Rev. A-P: заряжать только с выключенным плеером.** Светодиоды модуля могут указывать CHRG/STDBY, но их индикацию проверять для конкретной платы; они не заменяют измерение напряжения и тока.

## 6.3. BAT ADC — актуальная разводка

```text
Защищённый OUT+ ПОСЛЕ выключателя ──[100 kΩ]──┬── ESP32 GPIO36 / ADC1
                                               │
                                            [100 kΩ]
                                               │
System GND (OUT−) ──────────────────────────────┴── GND
                                               │
                                               +── [100 nF] ── GND (у ADC)
```

**Важно:** отсчёт идёт от **защищённого выхода после выключателя, до DC/DC**: при включённом плеере это приближение напряжения батареи; при размыкании защиты питание ESP32 отключится. Не подводить `B+` напрямую к включённой/выключенной системе в обход защиты. Два резистора **100k/100k** соответствуют прошивке; `Vbat = analogReadMilliVolts(GPIO36) × 2 / 1000` (В). При VBAT 4,20 В на ADC ~2,10 В, при 3,70 В ~1,85 В. Процент заряда в `Battery.cpp` ориентировочный, не использовать вместо аппаратной защиты.

**Контроль:** измерить напряжение на OUT± и у преобразователя мультиметром, сопоставить с ADC при нескольких уровнях разряда (например, 4,1/3,8/3,5 В), проверить `FEATURE_BATTERY_ADC=1` и `FEATURE_DEV_ENCODER=0`. Перед первым подключением к ESP32 проверить, что выход DC/DC остаётся около 3,3 В при пусковых токах Wi-Fi/BT + TFT + SD и не имеет опасных выбросов. Ток и переходные процессы измерять осциллографом/мультиметром; не пытаться делать выключатель только программной командой ESP32.

## 6.4. Порядок первого включения аккумуляторного режима

1. Убедиться в правильной полярности аккумулятора и идентифицировать все клеммы платы (`B±`, `OUT±`, USB 5 В). Проверить защиту и допустимый ток аккумулятора; прозвонить отсутствие КЗ.
2. **Выключатель нагрузки разомкнут.** Подать отдельные 5 В на зарядный модуль, измерить напряжение B±/OUT± и ток заряда, проконтролировать нагрев, затем отключить USB зарядника.
3. Не подключая ESP32, подключить DC/DC к защищённому OUT± через выключатель, измерить 3,3 В **с тестовой нагрузкой**, проверить пуск, пульсации и отсутствие перегрева.
4. Полностью отключить USB DevKit. Проверить по схеме именно своей DevKit отсутствие опасного обратного тока через её LDO/USB-UART, только потом подавать System 3V3.
5. Подключить остальную нагрузку поэтапно (TFT, SD, DAC, затем усилитель), проверить максимальное падение входного напряжения, помехи на аудио и реакцию на выключатель.
6. Перед новой зарядкой **выключить плеер** и отключить USB DevKit; подключить отдельный 5 В вход TP4056. Проверить остановку заряда и отсутствие заметного нагрева аккумулятора.

## 6.5. План максимум: Rev. B с BQ24074

**BQ24074 с power-path — вариант только для будущей интегрированной печатной платы**, когда потребуется работа плеера во время зарядки и единый USB-разъём. Потребуются полноценная схема по TI datasheet (входной лимит, зарядный ток, SYS/BAT, терморежимы), обратные токи/защита и повторная проверка силовой и аудиочасти. **В текущий BOM/распиновку/сборку Rev. A-P BQ24074 не входит.**

# 8. Установка окружения и первая прошивка

1. Установить **Arduino IDE 2.x** и пакет **esp32 by Espressif Systems 3.x** в Boards Manager. Для Arduino-ESP32 package URL: `https://espressif.github.io/arduino-esp32/package_esp32_index.json` (если не встроен).
2. Выбрать **ESP32 Wrover Module**, правильный COM/tty порт, PSRAM **Enabled** (если присутствует в меню), скорость Serial Monitor **115200**. Начать с штатных flash-настроек для конкретного модуля.
3. Через Library Manager добавить **Adafruit GFX Library**, **Adafruit ST7735 and ST7789 Library**, **ESP8266Audio**; зависимые Adafruit BusIO/другие библиотеки установить по подсказке IDE. Для `CLICKER_HARDWARE=2` добавить **Adafruit DRV2605 Library**.
4. Для `FEATURE_BLUETOOTH=1` дополнительно установить **ESP32-A2DP** автора pschatzmann, закрепить версию в журнале сборки. Интерфейсы библиотеки чувствительны к версии Arduino-ESP32/ESP-IDF. Если Source API несовместим — BT не считать собранным.
5. Из рабочего архива открыть **только** `DIY_iPod_Mono/DIY_iPod_Mono.ino`. До первой загрузки убедиться, что `#define FEATURE_BLUETOOTH 0` и `FEATURE_SD_FORMAT 0`.
6. Подключить USB-UART, выбрать **Verify/Compile**, затем **Upload**. Если загрузка зависает — отключить периферию с GPIO2/5/15 и убедиться, что плата входит в download mode. Не замыкать неизвестные контакты 5 В и 3,3 В.
7. Открыть Serial Monitor 115200; должны появиться имя прошивки, диагностика microSD и `Ready`. Первая загрузка должна выполняться от USB **без Li-Po**. Только после этого подключать TFT/SD, затем I²S, затем управление и усилитель по отдельности.

**Как получить воспроизводимый билд:** в журнале записать точную версию `esp32`, версию ESP8266Audio, ESP32-A2DP, выбранный Board, PSRAM, флаги `Config.h`, использованную microSD и серийный лог. Библиотеки можно зафиксировать через экспорт проекта/локальный репозиторий; наличие исходников не равнозначно подтверждённой компиляции.

# 10. Bluetooth A2DP / AVRCP v0.8-rc — экспериментальный протокол

**Путь:** `Settings → Bluetooth → Paired Devices / Scan and Pair`. При `FEATURE_BLUETOOTH=0` отображается диагностический пункт. При `1` для подключения нужен работающий Bluetooth Classic стек, установленная совместимая **ESP32-A2DP** и настоящая гарнитура с A2DP Sink.

**Paired Devices:** показывает ESP-IDF Classic bond-записи, хранящиеся в BT stack/NVS. Имя, если однажды найдено, кэшируется отдельно по BD_ADDR в namespace `bt-labels`; при отсутствии кэша отображается MAC. `Select` — подключиться/отключиться; удержание Select **≥1,5 с** → модальное подтверждение удаления. Bond — сохранённые ключи, **не** свидетельство текущего аудиосоединения.

**Scan and Pair:** сканирует Classic inquiry, показывает найденные имена, выбор сохраняется по **адресу** при обновлении. Результаты старше 45 с не отображаются; повторное сканирование вызывается после завершения предыдущего. `Select` начинает A2DP соединение с адресом, затем GAP запрашивает необходимые подтверждения.

**GAP dialogs:** `ESP_BT_GAP_PIN_REQ_EVT` → ввод legacy PIN (обычно 4, максимум 16 знаков; `min_16_digit` требует 16). `ESP_BT_GAP_KEY_REQ_EVT` → SSP passkey, **ровно 6** цифр. `ESP_BT_GAP_CFM_REQ_EVT` → сравнение шестизначного числа и согласие. На экране PIN: вращать колесо для изменения цифры, Prev/Next — перемещать позицию, Next на последней позиции может расширять длину до предела, Select — отправить полный допустимый PIN, Menu — отклонить. На экране согласия `Play/Pause` = Yes; `Menu` = No. Все ответы идут через GAP reply API; события никогда не подтверждаются автоматически только по имени или типу устройства.

**A2DP:** при Bluetooth-выходе PCM подаётся в callback SBC sender, PCM5102A не используется. Базовый путь требует **44,1 кГц stereo PCM**; универсальный ресемплер для 48 кГц отсутствует. При смене output decoder перезапускается с начала трека; бесшовность не заявлена. Из-за общего 2,4 ГГц радио во время Wi-Fi Sync возможна деградация/прерывания; первое испытание выполнять при выключенном Wi-Fi.

**AVRCP:** кнопки гарнитуры `Play`, `Pause`, `Next`, `Previous` подаются в очередь от BT callback и исполняются в основном UI loop; обработка по key release, чтобы не дублировать down/up. `Play` не должен паузить играющий трек, `Pause` не должен возобновлять паузу. Обратная передача metadata/playback status на гарнитуру, абсолютная громкость и повторное подключение пока не подтверждены и **не входят в критерий готовности v0.8-rc**.

**Ограничение достоверности:** на момент документа **нет успешного полного Arduino compile с BT=1, реального bond, A2DP-передачи или сквозного теста AVRCP**. Для нужного fork/версии ESP32-A2DP следует проверить сигнатуры Source callback и GAP override; единственную регистрацию GAP сохраняет библиотека. До этого не переводить BT в дефолтный `1`.

# 12. Диагностика и поиск неисправностей

| Наблюдение | Вероятные причины | Где и чем проверить |
|:--|:--|:--|
| Boot loop / UART молчит | 3V3 просадка, неправильная страппинг-схема GPIO2/5/15, повреждён USB-UART | Напряжение на 3V3 при reset; отключить TFT/DAC/piezo; Serial 115200 |
| Экран белый | DC/CS/RST не подключён, подсветка отдельно, неверный ST7735 init/rotation | 3V3, CS=5, DC=22, SCK=18, MOSI=23; лог `display.begin()` |
| TFT работает, SD card fail | SD_CS/MISO, уровень питания, SPI конфликт | CS=21, MISO=19; обе CS HIGH на idle; попробовать FAT32 карту |
| Кнопки спутаны | неверные резисторы/ADC окна; GPIO34 без pull-up | Измерить мВ без нажатия и каждого клавишного состояния; исправить `Input.cpp` |
| Select удаляет пару и одновременно подключает | двойное событие долгого нажатия | Native regression test; событие `SelectLong` строго одно, без `Select` при отпускании |
| Wheel прыгает/крутит назад | касание при boot, сменён порядок секторов, длинные шумные провода | `touchRead()` на каждом пине, baseline без руки, фото реальной топологии |
| Звук медленный/низкий | неверный sample rate / BCLK | Проверить WS на осциллографе, в прежнем ESP8266 тесте важен кварц **26 МГц**, не 40 |
| PCM чистый, после TDA искажения | смещение, неверная развязка, обратная связь, перегрузка/неисправный модуль | VREF/DC на всех узлах, синус 1 кГц без нагрузки → эквивалент 32 Ом |
| На джеке постоянное напряжение | нет выходных конденсаторов или неверная одно-полярная схема | Измерить DC на Tip/Ring относительно Sleeve **до** наушников |
| BT не находит гарнитуру | телефон/наушники не в discoverable/pair mode, BT feature=0, API конфликт, Wi-Fi contention | Serial `BT: stack`, `inquiry`, RSSI, отдельно BT без Wi-Fi |
| BT видит, но не соединяет | неподходящий PIN/SSP, нет A2DP Sink, неподдерживаемые callback API | GAP auth events, bond count, A2DP connection state, лог с адресом |
| A2DP соединён, тишина | sink отключён, 48 кГц без resampling, PCM fifo пуст | Декодер/`switchBluetooth()`, 44,1 кГц тест, data callback счетчик |
| AVRCP не работает/двойное переключение | гарнитура не посылает events, down/up отданы оба | Лог raw key + isReleased, в UI лишь завершённое нажатие |
| При USB отключении reset | LDO dropout, power path, пик тока радио | Oscilloscope 3V3/GND в момент unplug, SYS батареи, ток/температура |

# 13. Механика и сборка корпуса

**Размеры ориентировочные**, не готовый STEP: экранная PCB 34,5×58 мм, активная область экрана ~28×35 мм, DAC ~19×38 мм, TDA1308 ~20×20×3 мм, Li-Po 54×38×4 мм; корпус порядка 70×125×20–25 мм. Раскладывать платы **по одной плоскости**, батарею за узлами только там, где отсутствует давление, а не делать штабель из высоких гребёнок Dupont. Программирование и подмена microSD должны оставаться доступными. Расположить аудиоусилитель ближе к джеку, держать его сигнальную землю и линии L/R вдали от антенны/питания TFT.

Предусмотреть светлый корпус с округлёнными углами, отдельную лицевую прозрачную **защитную вставку из оптического поликарбоната или PMMA** (не касаться поляризатора TFT), одну снимаемую заднюю крышку, винтовые стойки, доступ к HOLD/USB-C/3,5 мм и аккуратно оформленную накладку Click Wheel. Для чистого вида между TFT и прозрачной вставкой нужен одинаковый зазор/прокладка по контуру, исключающая нажим на LCD. Участок над антенной ESP32 оставить без металла и аккумулятора насколько позволяет компоновка.

# 15. Дополнение v0.8.1: дисплей RST, 1024+ треков и новая плата ESP32

## 15.1. TFT ST7735S — почему RST = −1

`constexpr int8_t PIN_TFT_RST = -1;` — установленное библиотекой Adafruit значение «аппаратная линия сброса не управляется GPIO». TFT RST **не оставлять плавающим**. Для старой проводки на оригинальном ESP32-WROVER: после проверки электрических уровней подключить RST дисплея к ESP32 `EN` (общая линия сброса). Можно использовать отдельный GPIO, но только после полной ревизии распиновки; тогда заменить `-1` на его номер. На WROVER GPIO16/17 могут быть заняты PSRAM, GPIO34–39 — входы без режима OUTPUT, GPIO6–11 — Flash, GPIO12 — опасный загрузочный strap. Не выбирать GPIO «на глаз».

## 15.2. Индекс: новый предел и проверка RAM

- В обоих `Config.h`: `MAX_TRACKS = 2048` вместо 350. При 1024 файлах предел сканирования больше не является препятствием.
- `UI.cpp`: страницы `Songs` и `Category` хранят только `songIndices`, заголовки видимых строк берутся из `media.at(...)`; для 1024 файлов больше не создаются ещё 1024 `String` с названиями треков.
- При доступной PSRAM `Library.cpp` резервирует место для индекса до начала обхода SD и избегает пикового перераспределения вектора.
- Serial 115200 теперь печатает модель SoC, объёмы Flash/PSRAM, свободный heap, число индексированных треков. **Физическая валидация 1024/2048 ещё не проведена**; на платах без PSRAM или с длинными ID3-тегами возможно исчерпание heap.
- Проверка: скопировать 1024+ аудиофайлов в `/Music`, открыть `Music → Songs`, пролистать начало/середину/конец, запустить первый и последний, выполнить повторное сканирование, сравнить `Library: ... tracks` и heap, затем включить Wi-Fi (и BT, если допустим по SoC). Повторить после холодного старта.

## 15.3. Неизвестная плата: 2× USB-C, RGB, «16 МБ»

Два разъёма USB-C, RGB-светодиод и заявленные 16 МБ могут соответствовать ESP32-S3 N16R8/N16R16, но идентифицировать плату по этим признакам нельзя. Использовать `BoardProbe/BoardProbe.ino`: прошить без подключённой периферии, Serial Monitor 115200, посмотреть `Model`, `Flash`, `PSRAM initialized`, `PSRAM total`, `Internal 8-bit heap`. Для платы с нативным USB, если монитор пуст, включить `USB CDC On Boot` или использовать UART-мост и корректный USB-порт.

**Критический конфликт:** ESP32-S3 **не поддерживает Bluetooth Classic**, следовательно встроенный A2DP Source / AVRCP из текущего проекта на нём недоступен. Bluetooth LE не является совместимой заменой. Нужно либо сохранить оригинальный ESP32 с Classic BT, либо добавить внешний A2DP/AVRCP аудиопередатчик с управляющим интерфейсом и изменить аудио-маршрутизацию. Перевод на S3 потребует самостоятельной полной карты GPIO; конфигурацию `DIY_iPod_Mono/Config.h` от WROVER на S3 без проверки **не переносить**: у S3 иные ADC, USB-пины, ограничения PSRAM и назначение LED. На платах ESP32-S3 RGB часто висит на GPIO48 либо GPIO38 (зависит от ревизии), сама по себе его установка работе не мешает.

**16 МБ Flash не равны PSRAM.** Flash хранит программу, ресурсные разделы, NVS-эмуляцию EEPROM; PSRAM — внешняя энергозависимая ОЗУ. В диагностике объёмы измеряются отдельно.

**Питание остаётся Rev. A-P с TP4056.** Два разъёма USB-C DevKit не превращаются в зарядный контроллер 1S. Не соединять параллельно 5 В разных USB/TP4056 и не включать аккумуляторный преобразователь одновременно с питающим USB без спроектированной развязки. BQ24074 — только план для Rev. B PCB.

# Codex — iPod 3G / iTunes USB interoperability, MonoPod (next milestone)

Ты работаешь в существующем репозитории **MonoPod**, версия **v0.8.5**. Основной профиль **ESP32-S3 N16R8**, 16 MB Flash, 8 MB OPI PSRAM, нативный USB GPIO19 D− / GPIO20 D+, SPI microSD FAT32, ST7735S 160×128, PCM5102A I2S, TP4056 (прототип), звуковая пьеза без haptic. Включён пользовательский `MonoPod Studio` по Wi-Fi (HTTP) и USB CDC `MPOD1`; **это НЕ iTunes**. Прошивка оригинального Apple iPod в проекте отсутствует, не притворяйся, что уже её исследовал.

## Цель

Разработать максимально совместимую с реальным **Apple iPod третьего поколения, A1040 (2003–2004, iPod OS 2.x)** USB-синхронизацию для iTunes с аппаратной и файловой идентификацией, жизненным циклом блокировки накопителя и точной интерпретацией `iTunesDB`. **Не путай:** iPod 2G (2002, FireWire), iPod 3G (A1040, FireWire + USB sync), iPod 4G (2004, Click Wheel), iPod classic 6G (2007, hash58). Целевая версия — **iPod 3G**; интерфейс MonoPod может выглядеть как 4G. iPod 3G не использует hash58. Исследуй Windows и, если возможно, macOS iTunes, версии совместимости и реальные дескрипторы. Не заявляй «100% идентичность» до проверки на iTunes.

## Входные данные и первичный аудит

1. Прочитай `README.md`, `CHANGELOG_v0.8.4.md`, новый `CHANGELOG_v0.8.5.md`, `docs/MonoPod_Sync_Mode_v0.8.5_RU.md`, `DIY_iPod_Mono/{SyncMode,UsbSync,WiFiSync,UI,Display,Library,IpodIdentity}.{h,cpp}`, `Studio/usb_sync.py` и `examples/S3_USB_MSC_Lab/S3_USB_MSC_Lab.ino`.
2. Составь таблицу **факт / источник / гипотеза / проверка**. Отдельно: USB VID/PID/bcdDevice, конфигурации/interfaces/endpoints, строки производителя/модели/serial, USB MSC Bulk-Only Transport, SCSI INQUIRY / REQUEST SENSE / READ CAPACITY / MODE SENSE / START STOP UNIT / PREVENT ALLOW MEDIUM REMOVAL, и дополнительные vendor-specific запросы/команды (если есть).
3. Найди доступный для законного исследования оригинальный **образ firmware именно iPod A1040** (укажи источник, SHA256 и подтвердись правильностью платформы; не бери iPod classic 6G). Если образ не предоставлен и законно доступного файла нет — явно пометь это как blocker, выполни максимально полное исследование из документации/открытых реализаций/USB-трасс и дай точный перечень необходимых образов и версий. Не включай защищённые бинарники Apple в репозиторий, не публикуй исходный proprietary-код или ключи.
4. В пределах имеющихся данных проанализируй формат/контейнер прошивки, таблицу разделов/область прошивки, PP5002/ARM7 firmware, точки USB/SCSI/дискового режима, индикацию `Do not disconnect`/`OK to disconnect`, условия переходов из воспроизведения в sync и обратно. Ghidra/radare2, поиск строк, структур и вызовов, ссылки на адреса и функции с оффсетами. Для каждого вывода — конкретный артефакт/адрес или источник, никаких выдуманных адресов.
5. Исследуй не только firmware: iTunes — USB **host**, и большую часть логики синхронизации выполняет сам компьютер. Сопоставь захват USBPcap+Wireshark (Windows), usbmon+Wireshark (Linux; libgpod/gtkpod при отсутствии iTunes), по возможности реальный iPod 3G, diff содержимого накопителя до/после синхронизации. Гипотезы о протоколе подтверждай трассами и файлами.

## Реализация: по этапам

**Этап A — спецификация/захваты.** Подготовь `docs/iPod3G/USB_DESCRIPTOR_REPORT.md`, `USB_SCSI_TRACE.md`, `ITUNES_SYNC_FLOW.md`, таблицы SCSI CDB/ответов, спецификацию формата USB и отдельную таблицу несовместимостей. Сначала изучи фактическое обнаружение iTunes и роль режима накопителя. Не путай iAP/serial accessory commands с синхронизацией старого дискового iPod.

**Этап B — storage ownership.** Встроить TinyUSB MSC в **основную** прошивку ESP32-S3 (не вместо неё), с переключением CDC↔MSC или композитным устройством только если подтверждено нужной версией iTunes. Использовать `SyncController::enter(SyncTransport::UsbMsc)` при реально подтверждённом входе в Sync Mode, который останавливает аудио, гасит пьезу, блокирует клавиатуру и экран, освобождает файловые дескрипторы и передаёт **эксклюзивное владение картой** USB MSC. CPU во время MSC **не должен** одновременно обращаться к тому же FAT32 через Arduino SD, включая сканирование, тему/логирование, Wi-Fi и `iTunesDB`. После корректного host eject/SCSI STOP UNIT: `flush`, unmount/снятие экспорта, remount локального FAT32, проверка, чтение базы, возврат UI. При внезапном обрыве — не считать запись завершённой; при повторной вставке только безопасное восстановление. Не принимай простое наличие VBUS/вставленный кабель за начало синхронизации; учитывай фактическое обнаружение/запрос хоста и архитектурное ограничение: старый iPod исторически мог начать Auto-Sync сразу после подключения.

**Этап C — iPod 3G identity.** По подтверждённым дескрипторам/запросам сделай независимый `Ipod3GUsbProfile` с build-time опцией `FEATURE_ITUNES_USB_MSC`; сохрани `FEATURE_USB_SYNC` для `MonoPod Studio` и не меняй его протокол без миграции. Никогда не обещай, что только Apple VID/PID и строка `iPod` гарантируют распознавание iTunes. Не записывай в eFuse данные, не подменяй серийники настоящих чужих устройств. `IpodIdentity` уже получает уникальный заводской MAC из eFuse и предоставляет стабильный GUID; при отказе NVS fallback. Сделай воспроизводимое, сохраняемое соответствие GUID/USB serial/SysInfo; строго различай Apple hardware serial, FirewireGuid и local device ID. Документируй юридические/драйверные ограничения USB IDs и совместимости.

**Этап D — носитель и `iTunesDB`.** Поддержать FAT32 (согласно реальной структуре раннего PC iPod); выводить фактическое количество 512-byte блоков/свободное место microSD, учитывать скрытые системные файлы, ограничения FAT32, «No medium» без SD (SCSI sense + правильные ответы на READ CAPACITY). Никаких мнимых «10/20/40 GB», если карта другого объёма. Изучить `iPod_Control/Device/SysInfo`, `iPod_Control/iTunes/iTunesDB`, `iPod_Control/Music/Fnn`, master/playlist records: `mhbd`, `mhsd`, `mhlt`, `mhit`, `mhod`, `mhlp`, `mhyp`, `mhip`, timestamps, path encoding, UTF-16, persistent track ID/DBID, album/artist/genre, playlists, play count и порядок записи. Используй libgpod только как источник ориентиров, проверяй конкретно iPod 3G. Не применяй hash58 от classic 6G к 3G. Парсер должен быть **ограниченный по размеру, устойчивый к некорректным длинам и глубине**, желательно потоковый, на ESP32-S3 PSRAM. До завершения синхронизации не читай частично изменённую базу.

**Этап E — операции и дедупликация.** Исходный iTunes host пишет музыкальные файлы и обновляет `iTunesDB`, так что устройству достаточно поддерживать корректный накопитель и после eject перечитывать базу. При редактировании метаданных и повторной синхронизации сохраняй соответствие по **persistent ID/DBID**, а не только по имени файла; обрабатывай удаление/замену/перенос треков без дублей. Не модифицируй файлы, пока MSC экспортирован хосту. Для нашей Wi-Fi/USB CDC-ветки сохрани существующие операции и безопасную замену.

**Этап F — поведение экрана.** MonoPod 160×128: чёрно-белый режим `SYNC`, значок USB или Wi-Fi, постоянно видимое `DO NOT REMOVE SD` и `DO NOT UNPLUG USB` / `KEEP Wi-Fi CONNECTED`. Исторический iPod 3G использовал предупреждение `Do not disconnect`, а не такой точно такой же дизайн. Когда USB MSC реально занят — ни один пользовательский ввод, даже long Select, не должен размонтировать карту. `OK TO DISCONNECT` только после подтверждённого eject/flush. Для Wi-Fi выход только по явному безопасному действию после завершения HTTP-транзакции.

**Этап G — аудиокодеки.** Отдельно проверь MP3, AAC-LC `.aac`, `.m4a` с MP4 demux, ALAC lossless `.m4a` на ESP32-S3 N16R8, пиковую RAM/PSRAM, загрузку CPU, underruns I2S. Ограничения codec/container явно выводи iTunes, не заявляй поддержку защищённых FairPlay файлов. Это следующая подсистема, не маскируй отсутствие воспроизведения за успешной USB-передачей.

## Проверки и критерии готовности

1. Для заданных iTunes версий (укажи ОС/версию) на ПК устройство обнаруживается именно как совместимый iPod 3G **по факту**, а не только как флешка.
2. `usbview`, `lsusb -v`, USBPcap/usbmon capture подтверждают правильные дескрипторы и SCSI ответы; нет записей на физический носитель без активного/разрешённого режима.
3. Показаны реальные ёмкость и свободное место карты, при вынутой карте — `NOT READY / MEDIUM NOT PRESENT`, запрещено копирование без подмены ёмкости.
4. В момент Sync аудио останавливается и всё пользовательское управление блокируется, экран всегда виден, ни CPU, ни другой сетевой/USB транспорт не монтирует microSD одновременно с MSC.
5. Сценарии: первая синхронизация, 1024+ трека, вторая без дубликатов, замена метаданных, удаление, редактирование плейлистов, безопасное извлечение, обрыв USB при idle / mid-write, восстановление карты, no-SD, большой носитель FAT32. Сохраняются CRC/hashes контрольных треков и базы.
6. Матрица тестов для firmware ESP32 / ESP32-S3: Bluetooth выключен в S3 на этапе компиляции; Wokwi и `Studio` не сломаны; `python -m pytest -q tests`; полный **реальный** Arduino-ESP32 build (только если toolchain установлен) и аппаратные тесты. Отдельно измерь USB FS, не обещай 480 Mbps.

## Необходимые артефакты

Сохраняй изменения в репозитории: код и тесты, `docs/iPod3G/*` с таблицей доказательств и разметкой USB-трасс, `docs/SYNC_IMPLEMENTATION.md`, changelog, текстовый план воспроизведения в iTunes и диагностики. Сначала дай `research` и минимальный безопасный стенд, затем кросспроверенные выводы и готовый код. **Нельзя выдавать догадки за подтверждённые протоколы, объявлять iTunes-compatible без реального теста или включать чужую закрытую прошивку в архив.** Если Apple firmware или реальные USB-трассы недоступны, фиксируй blocker и реализуй только то, что подтверждено общедоступными форматами и тестами.

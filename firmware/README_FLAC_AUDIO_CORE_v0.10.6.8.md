# MonoPod v0.10.6.8 — FLAC streaming + audio on Core 0

## Исправления

1. **FLAC STREAMINFO / Vorbis Comments:** во время индексации microSD читаются только FLAC metadata-блоки (не весь аудиофайл). Поддерживаются TITLE, ARTIST, ALBUM, GENRE, DATE/YEAR и длительность из количества сэмплов и частоты. Большие обложки пропускаются без загрузки в память. Комментарии с неизвестными полями игнорируются.
2. **FLAC чтение:** `ChunkedFlacSource` оборачивает `AudioFileSourceSD`. На S3 N16R8 с PSRAM целевой объём 2048 КиБ (2 МиБ). Чтобы сохранить свободную PSRAM под остальные подсистемы, буфер может занимать не более половины свободной PSRAM при выделении, затем автоматически уменьшается вдвое вплоть до 128 КиБ; при отсутствии PSRAM используется резерв 32 КиБ во внутренней RAM. Начальное чтение ограничено 12 КиБ, дальнейшее заполнение выполняется кусками до 4 КиБ на итерацию. Емкость буфера соответствует **приблизительно** 17–24 секундам при 0,7–1,0 Мбит/с (до заполнения) для ряда распространённых FLAC, но реальное время зависит от битрейта; воспроизведение начинается ДО полного заполнения.
3. **Перемотка FLAC:** вызывается `FLAC__stream_decoder_seek_absolute` по номеру аудиосэмпла, а не `seek` по байтам. Для файлов без таблицы поиска возможна заметная задержка при перемотке. При ошибке seeking decoder создаётся заново для восстановления состояния.
4. **Два ядра:** на ESP32-S3 звук запускается в отдельной задаче Core 0 (16 КиБ stack, priority 3), UI и ввод — в основном `loopTask` (обычно Core 1). Обращения к AudioEngine со стороны разных ядер синхронизируются рекурсивным FreeRTOS mutex. Если задача не создаётся, остаётся однопоточный fallback.
5. **Буфер I2S:** для S3 заданы 24 DMA-буфера по 512 байт — около 70 мс PCM при 44,1 кГц. Это помогает пережить обновление экрана по общему SPI (160×128 RGB565 при 16 МГц — ~20,5 мс полезной передачи плюс накладные расходы).
6. **Эксклюзивный I2S:** Wi-Fi/USB Sync и Bad Apple блокируют фоновую аудиозадачу, чтобы она не обращалась к I2S в процессе синхронизации или встроенного видео.
7. Версия обновлена в UI, UART, информации синхронизации и OTA.

## Тестирование

- 51 Python-тест пройден; 1 пропущен.
- Нативный тест парсинга STREAMINFO/Vorbis Comments на реальном FLAC (генерация через ffmpeg) пройден.
- Нативный тест кольцевого буфера (ранний старт, предварительная подгрузка, перемотка, EOF, непрерывность чтения 5 МиБ) пройден.
- **Arduino-сборка и испытания на ESP32-S3 не выполнялись.** Устранение треска и скорость старта требуется проверить на физическом устройстве.

## Важные детали

- TFT и microSD подключены к **одному SPI**. Вывод на разных ядрах не ускоряет физическую передачу по SPI: драйверы сериализуют транзакции. Не повышайте частоту TFT выше устойчивого значения, пока измерения не подтвердят пользу.
- Декодирование 24-бит/192 кГц FLAC значительно тяжелее обычного 16/44,1; не гарантируется реальное время при любом формате.
- Если в Arduino IDE включено `USB CDC On Boot`, настройки остаются прежними; протокол MonoPod Desktop / OTA не менялся.

### Проверка на плате

1. Запустить обычный MP3, заставить прокручиваться длинный заголовок, активно крутить колесо. Не должно быть треска.
2. Запустить FLAC с тегами, сравнить название/исполнителя/альбом и полную длительность.
3. Проверить FLAC 16/44,1 и 24/48. Посмотреть время до появления звука и работу перемотки на отметки 10%, 50%, 90%.
4. Переключиться в Wi-Fi Sync, обновить список/загрузить файл, выйти в меню и возобновить музыку.
5. Запустить Bad Apple, проверить MP3-дорожку видео и последующий выход в меню.
6. Снять UART лог при треске; важно сравнить наличие ошибок SD и уменьшение свободной внутренней RAM.

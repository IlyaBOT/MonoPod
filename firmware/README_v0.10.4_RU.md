# MonoPod v0.10.4 — BAV2 + Clock + UI + Cleanup

Основание: архив MonoPod v0.10.3 из текущего проекта.

## Изменения

- `BadApple.cpp/.h`, новый `BadAppleAudioSource.h`: BAV1 (без звука) и BAV2 (видео delta/RLE 2bpp 160x128 + отдельный MP3-сегмент в том же `.bav`). При старте видео музыка останавливается; поток MP3 декодируется через ESP8266Audio и существующий I²S / PCM5102A. Никакого копирования всего MP3 в RAM и никакого временного файла на SD.
- Видео от исходного приложенного MP4: 160x128, 15 FPS, 3466 кадров, 2-bit grayscale; звук mono MP3 44,1 кГц / 64 кбит/с. PCM на вход AudioOutputI2S — 16-битное. Размер 5 236 012 байт.
- `Display.cpp`, `UI.cpp`: Now Playing показывает Play-треугольник при воспроизведении и Pause при паузе; Wi-Fi на этом экране отсутствует, Hold на 1 px ниже.
- Заголовок Now Playing заменяется временем в формате `5:29 PM`, **только когда время установлено**. Без времени остаётся текст `Now Playing`.
- Backlight Timer: только 5, 10, 15, 30, 60 секунд. Старые сохранённые варианты 0/1/2/3/255 нормализуются к 10 секундам.
- ClockService: установка времени из MonoPod Desktop при Sync Mode по USB или Wi-Fi; необязательный NTP после подключения к домашней Wi-Fi-сети. POSIX TZ и выбор NTP сохраняются в NVS. При отключении NTP SNTP-сервис останавливается.
- Удалён Wokwi/ILI9341, макеты отдельных GPIO-кнопок, экспериментальный GPIO-энкодер, оставшиеся альтернативные ветки дисплея. Не найдено активной реализации отдельного датчика освещения.
- USB удалены текстовые команды MPOD1 v1-v3 (`PUT`, `DELETE`, `REPLACE`, `INFO`). HTTP удалены `/upload`, `/time` и старый путь без проверки CRC. Действующий MPOD1 **v4** и `/api/fs/upload` сохранены.

## Прошивка

Открой `DIY_iPod_Mono/DIY_iPod_Mono.ino` в Arduino IDE 2 под ESP32-S3 N16R8. Требуются версии Arduino-ESP32 3.x, ESP8266Audio, Adafruit GFX, Adafruit ST7735, SdFat v2 (при `FEATURE_SD_FORMAT=1`), и прежние зависимости проекта. `USB CDC On Boot` включить. Выбор разметки, учитывая схему Flash, согласовать с предыдущей стабильной v0.10.x.

**Полная компиляция Arduino-ESP32 и работа на реальной ESP32-S3 в этой среде не выполнены.** Код является исходной реализацией, требующей сборки/отладки на целевом оборудовании.

## BAV2

Скопируй готовый `badapple.bav` (отдельная ссылка) в **`/MonoPod/badapple.bav`** на microSD. Обычный MP4 или MP3 с `.bav`-расширением не подходит. Встроенный BAV1 без звука продолжает поддерживаться. Внутренний FFat здесь **не реализован**; видео играет с microSD. Внимание: при наличии старого `BadAppleEmbedded.h` он имеет приоритет над файлом SD — удали такой заголовок, если его добавлял вручную.

Чтобы собрать BAV2 самостоятельно:

```bash
python3 tools/convert_bav2.py input.mp4 badapple.bav --fps 15 --mp3-bitrate 64k
```

Требуется FFmpeg с `libmp3lame`. Проигрыватель рассчитан на FPS до 25, рекомендуемые 15 для полного кадра SPI 160x128. Совместная работа с декодером MP3 и точная синхронизация **не подтверждены аппаратно**; возможны пропуски аудио или кадров, которые потребуется устранить по реальным логам.

### BAV2, little-endian

- `magic[4] = "BAV2"`
- `uint16 width, height` (160,128)
- `uint8 fps` (1..25)
- `uint32 total_frames`
- `uint32 audio_offset`
- `uint32 audio_length`
- `uint8 codec` (1 = MP3)
- `[uint16 encoded_length][encoded_frame]` повторяется `total_frames` раз; идентичное BAV1 XOR delta/RLE, где старший бит управляющего байта означает пропуск нулевых XOR-байтов.
- MP3 от `audio_offset` до `audio_offset+audio_length`.

Декодер использует второй SD-дескриптор с ограничением диапазона, не перезаписывая позицию видеокадров.

## Часы: USB и Wi-Fi

Часы не имеют резервного RTC. После полного выключения время надо снова установить с ПК либо получить по NTP. NTP возвращает UTC — настройка часового пояса передаётся отдельно строкой POSIX TZ (например `UTC0`, `MSK-3`, `CET-1CEST,M3.5.0,M10.5.0/3`). По умолчанию `UTC0` и NTP выключен.

В состоянии Sync Mode:

- USB: `MPOD1 X CLOCK <UNIX_SECONDS> <HEX_UTF8_POSIX_TZ> <0|1>\n` -> `MPOD1 OK CLOCK_SET`.
- Wi-Fi: `POST /api/clock` (`application/x-www-form-urlencoded`) с `unix`, `timezone`, `ntp`.
- `/api/info` и `MPOD1 X INFO` возвращают `clock_unix`, `timezone`, `ntp_enabled`.

Параметр `ntp=1` запускает SNTP асинхронно при наличии Wi-Fi STA; без доступа к интернету время остаётся тем, которое установил ПК. Для USB NTP тоже можно включить заранее, синхронизация произойдёт после подключения к Wi-Fi.

В `MonoPodDesktop_ClockIntegration` — готовые исходники WinForms UserControl + транспортного адаптера. **Они не интегрированы в актуальный MonoPod Desktop**, поскольку исходники приложения не были приложены. Файлы следует добавить в существующее `.sln` и подключить к действующему транспортному сервису.

## Ревью / открытые ограничения

1. BAV2 проверен по структуре и восстановлению всех видеокадров; аппаратный I²S, FPS и A/V-sync ещё не проверены.
2. SNTP использует публичные серверы и требует DNS/доступа в интернет; локальная сеть без интернета подходит для PC time sync, но не для NTP.
3. Проект не реализует FFat для Bad Apple, хотя раздел 9,9 МБ может использоваться в будущем.
4. HTTP API доступен в локальной сети во время Wi-Fi Sync и не имеет отдельной авторизации: не пробрасывать HTTP-порт во внешнюю сеть.
5. Нельзя одновременно использовать новое старое MonoPod Desktop/CLI, вызывающее старые протоколы: нужен клиент MPOD1 v4.
6. `WiFiSync` сохраняет старую командную модель активации Sync Mode: подключения к Wi-Fi недостаточно для записи файлов.
7. Переход к более длинным видео ограничен microSD и памятью декодера, поэтому проверять на реальной плате по частям.

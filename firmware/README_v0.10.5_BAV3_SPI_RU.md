# MonoPod Firmware v0.10.5 — BAV3 / SPI tuning

База: последняя доступная рабочая ветка v0.10.4 с USB CDC/подсветкой/ADC из `MonoPod_v0.10.4_USB_Backlight_Diagnostics.zip`. Новые изменения: BAV3 6-битный grayscale и RGB565, индивидуальная частота кадров из заголовка, разделённые настройки SPI. Протокол USB MPOD1 v4 не менялся.

## Совместимость форматов

| Формат | Пиксели | Звук | Воспроизведение в новой прошивке |
|---|---|---|---|
| BAV1 | GRAY2, 2 bpp | нет | да |
| BAV2 | GRAY2, 2 bpp | MP3 (если имеется) | да |
| BAV3 | GRAY6, 6 bpp | MP3 опционально | да |
| BAV3 | RGB565, 16 bpp | MP3 опционально | да |

Все форматы в текущем **плеере** требуют 160×128. BAV3 хранит fps в uint16: поддерживает 1..120 FPS на уровне файлового формата и конвертера; практический FPS определяется дисплеем и CPU. Значение 20 FPS не зашито в декодер. 20 FPS рекомендованы для *этого* видео Bad Apple. Цветной видеоплеер с масштабированием и выбором файлов из общего списка — отдельная будущая задача.

### Заголовок BAV3 (25 байт, little-endian)

| Смещение | Тип | Назначение |
|---|---|---|
| 0 | char[4] | `BAV3` |
| 4 | uint16 | width, 160 |
| 6 | uint16 | height, 128 |
| 8 | uint16 | FPS |
| 10 | uint32 | количество кадров |
| 14 | uint32 | смещение аудиосегмента, конец кадров |
| 18 | uint32 | размер аудиосегмента |
| 22 | uint8 | codec 0=нет, 1=MP3 |
| 23 | uint8 | pixel_format 1=GRAY6, 2=RGB565 |
| 24 | uint8 | reserved=0 |

Каждый кадр `[uint16LE size][RLE(delta-XOR)]`, где RLE использует контрольные байты: бит7=1 — пропуск `((control & 0x7f)+1)` нулевых дельта-байтов, бит7=0 — `count` буквальных XOR-байтов. Первый кадр относительно нулевого буфера. GRAY6 хранится как 4 пикселя/3 байта, от старших битов к младшим; RGB565 хранится little-endian. Данные MP3 идут *после* всех кадров, отдельным сегментом. В декодере буфер кадра выделяется динамически (предпочтительно PSRAM): 15 360 или 40 960 байт; на стеке таких буферов нет.

## Конвертация

Требования: Python 3 и FFmpeg в PATH.

```
python tools/convert_bav3.py "BadApple.mp4" badapple.bav --fps 20 --pixel-format gray6
```

Цветное видео:

```
python tools/convert_bav3.py "clip.mp4" color.bav --fps 30 --pixel-format rgb565
```

Тест первых двух секунд:

```
python tools/convert_bav3.py "clip.mp4" short.bav --fps 20 --pixel-format gray6 --seconds 2
python tools/inspect_bav3.py short.bav
```

Переносить на microSD в `/MonoPod/badapple.bav`. Твой ролик 231,13 с конвертирован в 4621 кадр, 20 FPS, 64 градации серого + MP3 44,1 кГц mono 64 кбит/с. Размер 11 391 764 байта (**10,86 МиБ**) — НЕ помещается в FFat-раздел 9,9 МиБ. На microSD подходит. При 20 FPS реальные кадровые интервалы — 50 мс; при недостатке CPU/MP3 кадры могут приходить с запаздыванием.

## SPI: изменяемые константы

В `Config.h`:

```
constexpr uint32_t SPI_SD_HZ = 8000000;
constexpr uint32_t SPI_TFT_HZ = 16000000;
```

* microSD: рабочая 4 МГц в предыдущей ревизии. Пробная 8 МГц; при ошибках монтажа/CRC вернуть 4 МГц; после подтверждения можно пробовать 12/16 МГц.
* ST7735S: рабочая 16 МГц. Увеличение до 20 МГц или 26 666 667 Гц — **экспериментальный разгон** без гарантий. В даташитах ST7735(S) встречается минимальный период записи SPI около 66 нс (≈15 МГц). Тестировать стабильность изображения, отсутствие полос/мусора и нагрев. Если искажения — вернуть 16 МГц.
* TFT и microSD на общем SPI используют раздельные CS; драйверы должны использовать транзакции и настройки скорости соответствующего ведомого.
* SPI0/SPI1 чипа обслуживают Flash/PSRAM и не предназначены для внешней SD/TFT; внешние устройства используют периферийный SPI2/SPI3.
* Software SPI не рекомендуется: у ESP32-S3 есть аппаратный SPI и DMA, bit-banging замедлит обмен и займёт CPU, нужный для MP3.

Расчёт **нижней границы** времени передачи целого RGB565 кадра 160×128: 40960 байт, 327680 бит. При 16 МГц — 20,48 мс; при 20 МГц — 16,38 мс; при 26,67 МГц — 12,29 мс. Реальное время больше из-за команд, row transfer, SD и работы декодера. Приблизительный `draw_avg` и фактический `fps` выводятся раз в пять секунд по диагностическому UART0 строкой `[BAV] ...`.

## Испытания

* `python -m pytest -q tests`: 22 passed, 1 skipped (на текущей среде).
* Native тест `BavPixel.h`: `g++ -std=c++17 -Wall -Wextra -Werror tests/bav_pixel_native_test.cpp -o bav_test && ./bav_test`.
* `tools/inspect_bav3.py` декодирует весь поток и сверяет количество кадров, структуру и границы MP3.
* Проверены короткие клипы BAV3 в 6-bit 20fps и RGB565 30fps при конвертации через ffmpeg.
* **Полная Arduino-ESP32 компиляция и испытания на реальном ESP32-S3/ST7735S/SD/PCM5102A не выполнены.** Аудио+20 FPS должно быть отдельно измерено на плате.

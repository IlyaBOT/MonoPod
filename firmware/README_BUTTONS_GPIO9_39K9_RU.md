# Исправление кнопок ESP32-S3 GPIO9 (без смены версии прошивки)

Исходник: MonoPod **0.10.6.1**, вариант Boot/HOLD/BTNS ADC Fix.

Точная схема, подтверждённая пользователем: пять NO-кнопок подключены между GPIO9 и GND через индивидуальные резисторы. Подтяжка **только внутренняя INPUT_PULLUP**, никаких внешних подтягивающих резисторов. MENU=0 Ом, PREV=5.1 кОм, NEXT=10 кОм, PLAY=20 кОм, SELECT=39.9 кОм.

Расчёт при VDD=3.3В и внутренней подтяжке 45 кОм (значения приблизительны):

| Кнопка | Ожидаемое мВ | Принимаемое окно мВ |
|--|--:|--:|
|MENU|0|0–120|
|PREV|336|180–480|
|NEXT|600|490–830|
|PLAY|1015|845–1330|
|SELECT|1551|1360–2100|
|нет нажатия|около 3300|все остальные диапазоны → NONE|

Особенности:
- Промежутки между окнами намеренно запрещены: шум и ошибочные уровни не должны вызывать соседние кнопки.
- Значение должно быть стабильно 60 мс; после включения/HOLD требуется 100 мс состояния «все отпущены», иначе нажатия временно игнорируются.
- Схема оригинальной ESP32 с GPIO34 и внешней подтяжкой не менялась.
- В дев-консоли UART0 (115200 бод) `$BTNS_ADC` включает вывод напряжения GPIO9, сырых значений, определённой кнопки и состояния ARMED; `$BTNS_ADC=0` выключает. `$BUTTON_ADC` показывает напряжение один раз.
- Если в режиме **без нажатия** консоль показывает менее 2.3 В, либо постоянно прыгает между 0 и 2 В, проблема в подтяжке/проводке/ADC, а не в номинальных границах кнопок. Не расширять окна до таких значений — иначе будут ложные нажатия.
- При непопадании фактических уровней в окна скорректировать `BUTTON_ADC_WINDOWS_MV` по измерениям *в конкретной схеме*, не расширять вслепую.

Тестирование Arduino на физической плате в этом окружении не выполнялось.

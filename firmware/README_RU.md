# MonoPod S3 DevTest v1 — независимая диагностическая прошивка

## Для чего

Это **новый минимальный скетч**, не использующий код MonoPod 0.8.x, `AudioGenerator`/`AudioOutputI2S`/Clicker/Settings/Wi-Fi. Он нужен, чтобы изолировать ошибки периферии и проверить, **повторяется ли звук на PCM5102A без аудиомикшера**.

При загрузке:

1. UART0 (USB-UART/второй Type-C) открывается на **921600 бод**.
2. На пьезоэлементе GPIO42 звучит **один сигнал 896 Гц, 110 мс**.
3. Инициализируются SPI, ST7735S, I²S TX (PCM5102A), ADC GPIO4.
4. На ST7735S показывается вращающийся 3D каркасный куб, FPS и состояние SD.
5. **Каждые 5 секунд** идёт попытка монтирования SD через SPI на 400 кГц. При первом успехе скетч создаёт/дописывает `/SD-Card_init-success.txt`, печатает размер карты и прекращает все последующие обращения к SD (не отключает физически общую SPI-шину, потому что она нужна TFT). Если запись файла запрещена — отдельно пишет `WRITE_FAILED`.
6. Команда `UPLOAD=16000,1` переводит в YMODEM CRC16. Экран становится **чёрным с красной надписью RECEIVING CONTENT**, нет ни анимации, ни попыток SD, ни вывода диагностики в UART посреди бинарного протокола.
7. После полного подтверждённого приёма PCM16 в PSRAM, GUI и повторные проверки SD возобновляются. Аудио передаётся в PCM5102A через **отдельный I²S драйвер ESP-IDF** ровно один раз; после конца подаются нули, передача останавливается и буфер PSRAM освобождается.

**Не используются** Wi-Fi, touch wheel, физические кнопки, звук Clicker в основном MonoPod, MP3/AAC декодер. Это сознательная изоляция источника I²S-багов. Существующая прошивка будет заменена на время диагностики; данные NVS и microSD сохраняются, кроме указанного файла.

## Подключение ESP32-S3 N16R8

| Устройство | Контакт | GPIO |
|---|---|---|
| ST7735S 1.8″ | SCK/SCL | 12 |
| ST7735S | SDA/MOSI | 11 |
| ST7735S | CS | 10 |
| ST7735S | DC | 39 |
| ST7735S | RST | 47 |
| microSD | SCK | 12 |
| microSD | MOSI / DI | 11 |
| microSD | **MISO / DO** | **13 (обязателен!)** |
| microSD | CS | 14 |
| PCM5102A | BCK | 16 |
| PCM5102A | LRCK/LCK | 17 |
| PCM5102A | DIN | 18 |
| Пьезо | Signal | 42 |
| Аналоговый вход | Battery ADC (через 100k/100k) | 4 |

Питание TFT, SD, PCM5102A проверять по документации **конкретных модулей**, земля общая. Подсветку TFT на 30 мА **не подключать напрямую к GPIO15**. В этой версии GPIO15 не используется по умолчанию (`HAS_P_CHANNEL_BACKLIGHT_KEY=false`): подсветка питается отдельно, от проверенной 3,3 В схемы. Не соединять питание двух USB-C и внешнюю батарею без готовой схемы power-path.

## Настройки Arduino IDE

- Board: ESP32S3 Dev Module.
- Flash Size: 16MB.
- PSRAM: OPI PSRAM.
- Arduino-ESP32: 3.3.x (разработка ориентирована на 3.3.12).
- USB CDC On Boot: может оставаться Enabled, но **консоль для теста — `Serial0`/UART0**, а не Native USB CDC.
- Установить через Library Manager: **Adafruit GFX Library**, **Adafruit ST7735 and ST7789 Library** (и Adafruit BusIO, если попросит менеджер).
- `SD.h`, `SPI.h`, `driver/i2s_std.h` входят в ESP32 core.
- Открой `MonoPod_S3_DevTest/MonoPod_S3_DevTest.ino`.
- Выбери COM-порт второго Type-C (USB-UART). Если используешь только Native USB-C — этот тестовый скетч не будет принимать YMODEM через него; нужен UART0.
- Скорость терминала **921600, 8N1**. Для нестабильного USB-UART можно заменить `UART_BAUD` в скетче на 115200 и передать Python-скрипту `--baud 115200`.

## Проверка без аудио

Ожидаемый лог:

```text
=== MonoPod S3 standalone hardware / audio dev test ===
PIEZO startup: 896 Hz x 110 ms (once)
I2S ready: GPIO16 BCK / GPIO17 LRCK / GPIO18 DATA, 16-bit stereo TX
READY. Commands: HELP, INFO, UPLOAD=16000,1, SD_NOW
SD_ATTEMPT=1 SPI=400000
SD_MOUNT=FAIL (...)
```

Если microSD обнаружена:

```text
SD_MOUNT=OK size=... bytes FILE=CREATED; SD probing stopped
```

Если карта вставлена, но она не видится, проверить в порядке: земля/3,3 В, MISO GPIO13, CS GPIO14, SCK GPIO12, MOSI GPIO11, качество соединений, FAT32, другую карту. В этом тесте TFT и SD пользуются общим `SPI` и раздельными CS. `SD_MOUNT=FAIL` не инициирует форматирование.

Дополнительная команда `SD_NOW` запускает немедленную попытку, пока SD не отмечена успешной. `INFO` показывает доступный максимальный непрерывный блок PSRAM (минус 128 КБ резерва). Каждые 5 секунд выводится `BAT_GPIO4 raw=... calibrated=... mV`; это чтение **без умножения на два**. Сравни его с измерением мультиметром 1,97 В на GPIO4.

## Загрузка аудио в PSRAM через Python + YMODEM

### Установка на Windows

```powershell
py -m pip install -r tools\requirements.txt
```

Чтобы передать MP3, AAC, FLAC, M4A или WAV, нужен `ffmpeg` в `PATH` — преобразование выполняется **на компьютере**, чтобы исключить декодер с ESP32.

### Короткий 896-Гц тест без FFmpeg

```powershell
py tools\send_audio_ymodem.py --port COM7 --tone --tone-seconds 2
```

### Передача настоящего трека

```powershell
py tools\send_audio_ymodem.py --port COM7 --file "C:\Music\test.mp3" --rate 16000 --channels 1
```

Ключи `--rate 16000` и `--channels 1` выставляют моно PCM16LE 16 кГц. Это **низкое качество, но максимально долгий тест, умещающийся в PSRAM**. Для проверки стерео/качества использовать `--rate 44100 --channels 2` (сильно снижает максимальную длительность).

**Ограничение PSRAM:** сырое PCM16 занимает `sampleRate × channels × 2 × seconds` байт. При доступных ~7,4 МБ 16 кГц/моно = около 4 минут; 44,1 кГц/стерео = около 40 секунд. Максимум точно выведет команда `INFO` на устройстве. Если аудио слишком большое — Python-сценарий может попытаться загрузить его, но ESP32 ответит отказом в ходе заголовка. Уменьши `--rate`, используй `--channels 1` или обрежь трек через ffmpeg.

Приём **YMODEM-CRC**: стартовый блок 128 байт (имя и длина), блоки данных 1024 байт, CRC-16/CCITT, подтверждения ACK/NAK, два EOT, завершающий пустой блок. YMODEM передаёт только один файл `.pcm` за сеанс. Сторонние программы передачи YMODEM могут работать, если используют эту стандартную последовательность, но рекомендуем комплектный Python-клиент.

Во время передачи не пользуйся Arduino Serial Monitor и не открывай тот же COM-порт в другой программе: порт одновременно должен занимать только Python-клиент. При прерывании не отключай питание, дождись 16-секундного таймаута приёмника либо перезагрузи плату. Буфер не сохраняется в Flash/на SD.

### Что фиксировать осциллографом

- После загрузки: **один** 110-мс сигнал на GPIO42 (896 Гц).
- Во время приёма: на I²S BCK/LRCK/DIN нет вновь запущенного аудио (канал готов, но не включён).
- После завершения: BCK GPIO16 и LRCK GPIO17 активны только на протяжении воспроизведения и короткого дренирования DMA; DIN GPIO18 отражает PCM16; затем I²S TX отключён. ЦАП PCM5102A может удерживать уровень или вести себя по своей схеме mute — оценивать **аналоговый выход** после декодера отдельно.
- Команда `INFO` после `AUDIO_DONE` должна показывать освобождённую PSRAM.

# MonoPod Desktop 1.1.2: подключение после Cancel

## Исправленное поведение

Cancel safely останавливает передачу и очередь. Подключение остаётся доступным для следующей операции. Если отмена произошла до бинарной передачи, используется тот же открытый USB-порт.

При прерывании бинарного блока текущая прошивка 0.10.6 не предоставляет отдельной команды отмены внутри потока данных. Поэтому Desktop закрывает прерванный поток, ждёт безопасный интервал до 18 секунд с последней записи, открывает новое соединение, проверяет HELLO/INFO и восстанавливает прежнее состояние Sync. Ручное нажатие Connect после успешного восстановления больше не требуется. Во время ожидания интерфейс показывает этап восстановления.

Активный USB Sync остаётся активным. При исходно неактивном Sync соединение сохраняется без включения Sync. Каталог обновляется без чтения метаданных, чтобы сразу после Cancel не начинать новую бинарную передачу. Отменённый файл и очередь автоматически не запускаются. Если отмена совпала с последним подтверждением сохранения, проверьте целевой файл перед повтором.

Disconnect, закрытие программы и ошибки транспорта по-прежнему освобождают соединение. Если повторное открытие порта или проверка устройства не удались, Desktop показывает ошибку и отключённое состояние.

## Причина и изменения

Обработчик OperationCanceledException безусловно вызывал CloseTransport для USB. Восстановление из 1.1.1 завершало Sync и удаляло транспорт из интерфейса, поэтому пользовательский Cancel приводил к отключению.

- `MonoPod.Core/UsbMonoPodTransport.cs`: общий безопасный путь восстановления; новый RecoverAfterCancellationAsync сохраняет новое соединение и подтверждает требуемый Sync. Старый RecoverAndEndSyncAsync остаётся для аварии и отключения.
- `MonoPod.Desktop/Forms/MainForm.cs`: отдельный путь пользовательской отмены, независимый таймаут восстановления, обновление каталога без метаданных. Cancel в диалоге конфликтов явно отменяет токен операции.
- Номер приложения и сборок: 1.1.2 / 1.1.2.0. Прошивка и Legacy Studio не изменялись.

## Проверка

122/122 теста прошли, включая шесть новых проверок:

1. Прерванная загрузка, повторное подключение и успешная следующая загрузка без ручного Connect; сохранность старого файла в модели протокола.
2. Восстановление подключения с неактивным Sync.
3. Сохранение здорового порта без повторного открытия и END.
4. Отказ восстановления при неподдерживаемом HELLO с закрытием нового порта.
5. Полный WinForms-путь отмены: подключение остаётся, Disconnect доступен, каталог обновлён, новые бинарные чтения метаданных не начаты.
6. Отмена до бинарной передачи оставляет исходный порт и интерфейс подключёнными.

Это программные проверки с моделью USB-устройства и настоящим WinForms-кодом. В тестах задержка приёмника обнулена; безопасный интервал отдельно покрыт прежними тестами 1.1.1. Намеренный обрыв передачи на физическом плеере для 1.1.2 не выполнялся. Успешный контрольный физический тест 32 КиБ относится к предыдущей 1.1.1 и не считается проверкой Cancel.

Логи тестов, публикации и запуска portable-сборки: `docs/validation-1.1.2/`. Запуск новой версии: `publish/win-x64-1.1.2/MonoPod.Desktop.exe`; папку нужно переносить целиком. Настройки AppData сохраняются. Работающий экземпляр 1.1.1 и его каталог не заменялись.

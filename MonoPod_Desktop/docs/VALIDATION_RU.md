73 C#-теста используют состояние файла/пакета для USB и настоящий loopback-сервер для HTTP; нативные C++-проверки компилируют актуальные исходники прошивки. Исторические проверки обновлены под общий SyncFiles, новое имя флага STA и доступный Windows-шрифт. Три GCC-зависимые обвязки явно пропущены, поскольку g++ отсутствует. Отдельно MSVC скомпилировал и выполнил проверку консольного парсера, подсветки, Wi-Fi RSSI и штатных глифов. Это не аппаратные тесты.

Тесты покрывают HELLO/INFO без автоматического входа в Sync, START/END, существующую USB-сессию при повторном подключении, передачу нескольких блоков, CRC, повторную попытку, замену без дублей, обрыв/таймаут/неверный NEXT, отсутствие текстовых команд после прерванного пакета, UTF-8 пути, пустые файлы/каталоги, 2101 запись, запрет выхода из корня и локальной папки скачивания, статусы HTTP 404/500, потерю HTTP-соединения, запрет операций вне Sync, старый Wi-Fi API, темы через оба транспорта, MPT1/MPT2, повреждённые заголовки/глифы/CRC и кириллицу.

Настоящий C++ SyncFiles проверен на изолированной файловой системе: старая версия сохраняется при плохом CRC, отмене и ошибке rename; восстанавливается backup после моделируемой незавершённой замены. Настоящий UsbSync.cpp проверен с блочными данными, содержащими текст `MPOD1 SYNC END` внутри файла: они остаются данными. Драйвер SD, питание, FAT-кэш и физическая линия USB этим не воспроизводятся.

## Arduino сборки

Обе финальные компиляции Arduino-ESP32 3.3.12 завершились успешно. Проверено соответствие исходников в build snapshot текущим `.cpp/.h`; сгенерированный sketch содержит версию 0.10.0 и финальные вызовы восстановления/индексации.

Результаты — `firmware-build-summary.json`; полные журналы — `build-s3.log` и `build-esp32.log`. В `../firmware-builds/` находятся `.bin`, `.elf`, `.map` и SHA-256-манифесты каждого профиля. ## Регресс запуска v0.9.0

ELF из кэша Arduino совпал с SHA-256 в пользовательском crash log. Декодирование показывает переполнение стека при сканировании SD до инициализации TFT: два кадра по 4416 байт превышают loopTask 8192 байта. Локальный 4096-байтовый MP3-буфер перенесён в ограниченное выделение heap с обработкой отказа. В финальных ELF обоих профилей кадр сканера — 352 байта; `tools/verify_firmware_stack.py` успешно проверил этот предел. Нативный тест настоящего Library.cpp прошёл вложенные каталоги до глубины 6, ограничение глубины, Xing/WAV/пустой MP3, rescan и eject. Подробнее: [BOOT_REGRESSION_RU.md](BOOT_REGRESSION_RU.md).

## Проверка на устройстве — UNVERIFIED

1. Native USB ESP32-S3 N16R8: реальный COM, идентификация версии, вход/выход Sync, остановка звука и нормального управления, чтение каталогов и больших файлов. USB-UART должен остаться консолью.
2. Загрузка/замена/скачивание, реальная CRC/размер, извлечение кабеля на разных границах блока, восстановление после повторного подключения; повторить с расходной резервной копией карты.
3. Wi-Fi через действующий STA: сохранение LAN IP, пропадание роутера и возврат, AP fallback при отсутствии STA, отсутствие одновременного USB-писателя. HTTP рассчитан на доверенную локальную сеть.
4. Физическое прерывание питания во время rename/flush/очистки журнала. Программный журнал не гарантирует стойкость самой FAT/контроллера SD при произвольном отказе питания.
5. Темы через оба транспорта: активация и откат, MPT1/MPT2, все цвета, кириллица, сглаживание на реальном ST7735S. Сопоставить видимый дисплей с предпросмотром.
6. Оригинальная ESP32: свободный непрерывный heap после индексации, установка темы без PSRAM, воспроизведение и Wi-Fi. На S3 Bluetooth Classic отсутствует по препроцессору. GPIO и независимые аппаратные модули не менялись.
7. Фактический Windows DPI 125/150%, переход между мониторами и Windows 10. Здесь проверены живой интерфейс Windows 11 при 96 DPI и логическое масштабирование; системный DPI не менялся.

## Ограничения

- Размер одного файла до 1 GiB; путь до 240 UTF-8 байт, компонент до 90. Внутренние области /MonoPod и /iPod_Control защищены; тема устанавливается отдельной операцией. Папки удаляются только пустыми; скачивание каталога целиком не реализовано и обозначено Unsupported.
- При отмене в момент окончательного commit операция могла уже завершиться; после переподключения обновите каталог и проверьте целевой файл. Нет возобновления с середины. После прерванного USB бинарного пакета повторить подключение спустя 18 секунд и отправить файл заново. Незавершённый HTTP upload может очищаться по 15-секундному таймауту. До завершения операции Sync не освобождается.
- Индекс самого плеера по-прежнему ограничен 2048 треками и глубиной MAX_SCAN_DEPTH; файловый менеджер этого ограничения не имеет.
- ID3 unsynchronisation/encryption и некоторые нестандартные теги не декодируются. Неизвестная длительность остаётся пустой/—. Битрейт MP3 относится к прочитанному MPEG-заголовку, а не гарантированному среднему VBR. Длительность CBR не оценивается по общему размеру.
- AAC — raw ADTS. M4A/ALAC не заявлены поддерживаемыми. Теги на устройстве читаются диапазонами, максимум 256 KiB на файл; кэш сбрасывается при операции и переподключении. При внешней замене тем же размером и FAT-временем требуется повторное подключение.
- GDI+ и Pillow/FreeType дают разные растры одного TTF. Проверено совпадение множества глифов и формата, но не обещано побайтное совпадение растеризации. Предпросмотр потребляет те же данные глифов, что экспортируются.
- При нехватке heap большая тема отклоняется с ошибкой активации. Предпочтение PSRAM не превращает её в обязательное условие; допустимый на конкретной плате максимум нужно измерить.
- Legacy firmware ограничена собственным API. Старый Wi-Fi upload и MPT1 темы сохранены; при загрузке темы используются четыре старых цвета. Для файлового менеджера и USB-тем нужна v0.10.0 / протокол v4.
- Авторизация HTTP и автоматическая прошивка устройства не добавлены. Опубликованная программа не требует Python.

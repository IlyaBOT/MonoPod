# MonoPod Desktop 1.2.1 — местное время и часовой пояс

Дата: 01.11.2026. Проверены актуальные исходники Desktop и `I:\DIY_iPod_Mono\MonoPod_v0.10.6.9`.

## Причина

В Desktop 1.2.0 `ShowClockInfo()` выводил `clock_unix` через `DateTimeOffset.FromUnixTimeSeconds` непосредственно как UTC. Рядом без преобразования отображалась строка `timezone` из прошивки. Поэтому правильному московскому времени 18:50 соответствовала вводящая в заблуждение надпись `15:50 UTC; timezone: UTC-3`.

Знак в POSIX TZ обратен привычному гражданскому смещению: `UTC-3` означает UTC+03:00, `UTC3` — UTC−03:00. Код передачи времени в Desktop корректно отправлял Unix timestamp без добавления трёх часов и `UTC-3` для московского пояса Windows. В прошивке `setUnix()` записывает этот timestamp без повторного смещения, а `dateTime()` и `shortTime()` вызывают `localtime_r`. Подмена передаваемого пояса на `UTC3` создала бы реальную ошибку.

Дополнительно в Config.h версии 0.10.6.9 пользовательский пояс по умолчанию был изменён на `UTC3`. Он исправлен на `UTC-3` с пояснением знака. Сохранённое значение NVS имеет приоритет над значением по умолчанию; существующие настройки автоматически не переписываются.

## Исправление

- Settings показывает **Device time: 2026-11-01 18:50:00 (UTC+03:00)**. Для расчёта используется пояс, реально прочитанный с плеера, независимо от ещё не применённого выбора в Desktop.
- Новый модуль `PosixTimeZone.Display.cs` декодирует фиксированные POSIX-смещения, дробные часы, секунды, имена в угловых скобках и явные годовые правила DST `M`, `J` и номера дней. Правила учитываются на момент timestamp, включая южное полушарие и границы года. Неизвестный формат явно отображается как UTC с предложением Apply.
- Unix timestamp, кодирование часового пояса для USB/HTTP, NTP, OTA и пользовательский профиль сохраняют прежнее поведение. Номер Desktop и файловых версий обновлён до 1.2.1 / 1.2.1.0.
- В исходниках прошивки 0.10.6.9 изменён только параметр по умолчанию в Config.h, добавлены нативная проверка и документация. Аудио, FLAC, распиновка, OTA и таблицы разделов сохранены.

## Как применить

1. Закройте Desktop 1.2.0. Распакуйте новый portable-архив целиком либо запустите `publish\win-x64-1.2.1\MonoPod.Desktop.exe`.
2. Подключитесь к плееру. Оставьте автоматический пояс Windows либо выберите `(UTC+03:00) Москва, Санкт-Петербург` вручную.
3. Нажмите **Apply clock settings and synchronize now**. При 18:50 на московском ПК Desktop должен показать 18:50 и UTC+03:00. Этим действием исправляется и ранее сохранённый неверный пояс на устройстве. Для исправления показанной ошибки перепрошивка не требуется.

## Проверки

Все 255 тестов .NET прошли: прежние 210 и 45 новых проверок. Новые проверки включают московский пример, обратный знак POSIX, смещения ±03:30/05:45, секунды, границы переходов DST, високосный год, разные сезоны шести часовых поясов Windows, неизвестные форматы и реальный код WinForms при масштабе геометрии 100/150%.

Нативные проверки прошивки: 32 проверки ClockConfigValidation, 24 проверки реального ClockService.cpp с адаптерами NVS/Wi-Fi/SNTP/времени, четыре теста WheelDetents и один отдельный тест реального Config.h через C runtime на ПК. Последний подтверждает, что `15:50 UTC` при заданном `UTC-3` преобразуется в `18:50`; меняется только TZ дочернего процесса, часы ПК и устройства не меняются.

Сборка и запуск portable проверяются с изолированным профилем. Снимки Settings находятся в `validation-1.2.1`. Полные результаты, изменения и хеши — в `verification-summary.json` и package-validation рядом с архивами.

Физический плеер не перепрошивался; реальная синхронизация USB/Wi-Fi/NTP в этой проверке не выполнялась. Полная новая сборка firmware BIN не выпускалась: изменение прошивки ограничено значением по умолчанию, а работающая версия получает правильные настройки существующей командой Apply.

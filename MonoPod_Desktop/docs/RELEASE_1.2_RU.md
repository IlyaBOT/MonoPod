# MonoPod Desktop 1.2.0 — Wi-Fi OTA, время и NTP

Дата: 01.11.2026. Исходники Desktop: `I:\DIY_iPod_Mono\MonoPod_Desktop`. Проверенная версия протокола: MPOD1 v4 и независимый OTA v1 из `I:\DIY_iPod_Mono\MonoPod_v0.10.6.6`.

## Что добавлено

Device → Firmware Update открывает полноценный процесс обновления по текущему Wi-Fi-соединению: получение возможностей и ID, выбор локального application `.bin`, проверка образа, ввод PIN с экрана, явное подтверждение, потоковая передача, ожидание подтверждения устройства и проверка версии после ручного повторного подключения. Старые прошивки с отсутствующим endpoint и устройства без двух OTA-слотов получают разные объяснения о первом обновлении через USB.

До отправки проверяются размер относительно живого OTA-слота, чип из ESP-заголовка, application descriptor, границы сегментов, checksum и встроенный SHA-256 при его наличии. Образ не преобразуется. После подтверждения SHA-256 вычисляется по исходному файлу; один открытый дескриптор без разрешения записи используется до конца передачи. Multipart имеет один файл и известный Content-Length. PIN передаётся только HTTP-заголовком, очищается из поля после попытки и не сохраняется в настройках, журнале или командной строке.

Во время OTA блокируются другие действия с устройством. Передача байтов, подтверждение `verified/rebooting` и реально прочитанная версия после перезагрузки — разные стадии. При обрыве или таймауте после начала POST результат обозначается как неизвестный. Нет автоматического повтора или обещания отката.

Время можно установить через Device → Synchronize time with PC или Settings → Apply clock settings and synchronize now. Поддерживаются USB и Wi-Fi. Для старой USB-прошивки команда требует временного Sync: приложение включает его и завершает после установки времени, если до операции он не был активен.

## Настройки

| Пункт Settings | Действие | По умолчанию |
|---|---|---|
| Automatically start Sync and load the music index on connection | Включить Sync, пересоздать индекс и прочитать Music при Connect | Выкл. |
| Automatically synchronize device time with this PC on connection | Установить время ПК, пояс и выбранные NTP-настройки при Connect | Выкл. |
| Device: automatically synchronize time over NTP when joining Wi-Fi | Сохранить автоматический NTP на плеере; затем он работает без Desktop | Выкл. |
| NTP server | Имя сервера или IPv4, без URL/порта | pool.ntp.org |
| Select timezone manually | Разрешить ручной выбор пояса из списка Windows | Выкл.; используется текущий пояс Windows |

Кнопка Apply немедленно применяет настройки и устанавливает время ПК. При включённом NTP его параметры также передаются при подключении. Если автоматическая установка времени ПК выключена, для уже выставленных часов сохраняется прочитанный Unix timestamp; если часы ещё не установлены, используется время ПК как начальное значение. Для отключения NTP на уже настроенном плеере снимите флажок и нажмите Apply.

Переходы летнего времени кодируются из текущего правила Windows в POSIX TZ. В ручном режиме выбирается понятное имя Windows, а не строка для прошивки. Редкие правила с переходом ровно 29 февраля отклоняются с объяснением. При изменении законодательных правил часового пояса примените настройки заново с обновлённой Windows.

## Изменения прошивки

NTP в исходной 0.10.6.6 уже был: в подключённом STA-режиме использовались pool.ntp.org и time.google.com. Добавлены редактируемый сервер, его проверка и сохранение в NVS, поле `ntp_server` в INFO и одноимённая capability. HTTP `/api/clock` принимает необязательный `ntp_server`, USB CLOCK — необязательный последний аргумент в hex. Старые клиенты сохраняют совместимость; при отсутствии аргумента сервер не меняется. Для старых прошивок Desktop не отправляет неизвестное поле и объясняет ограничение при выборе другого сервера.

При смене сервера или пояса SNTP перезапускается. После потери Wi-Fi он останавливается, после возврата сети запускается снова. Изолированная точка доступа Sync не даёт Интернет для NTP. Номер прошивки оставлен 0.10.6.6; наличие расширения определяется по capability, а не по имени BIN.

Полная сборка выявила исходный конфликт `WheelDetents.h` с макросами Arduino PI/TWO_PI. Переименованы только две приватные константы, формулы и параметры колеса сохранены. Старые четыре теста интерполяции проходят также с заранее объявленными макросами Arduino.

Исходная прошивка целиком сохранена в `work/ota-time-2026-11-01/firmware-before-clock-extension.zip`. Исходное состояние Desktop сохранено в `before-1.2.zip` в той же папке. Оригинальные OTA-сервис, таблица разделов, пароль Wi-Fi, старые прошивки и Legacy Studio не менялись.

## Файлы и точки интеграции

- `MonoPod.Core/ClockConfiguration.cs`: проверка часов/NTP и перевод пояса Windows в POSIX.
- `MonoPod.Core/FirmwareImage.cs`, `OtaModels.cs`, `WiFiMonoPodTransport.Ota.cs`: образ, OTA-протокол, исключительное владение HTTP-соединением, результат и сверка после reboot.
- `Models.cs`, `UsbMonoPodTransport.cs`, `WiFiMonoPodTransport.cs`: поля часов и команды установки времени; локальный HTTP без прокси и перенаправлений.
- `MonoPod.Desktop/Forms/FirmwareUpdateForm.cs`, `MainForm.DeviceFeatures.cs`: окно OTA, настройки, автодействия, отдельная проверка результата. MainForm и Preferences подключают эти функции к существующему Run/Cancel и JSON-настройкам.
- Новые тесты: FirmwareImageTests, OtaClientTests, OtaNetworkTests, ClockTests, UiDeviceFeatureTests и OtaTestSupport. Прежние тесты USB, файлов и тем сохранены.
- В прошивке: ClockService.cpp/h, ClockConfigValidation.h, WiFiSync.cpp, UsbSync.cpp, SyncFiles.cpp, WheelDetents.h; тесты и `tools/run_clock_native_tests.py`.

Полный перечень с хешами и результатами находится в `validation-1.2.0/verification-summary.json`.

210/210 тестов .NET прошли. Они покрывают HTTP multipart/Content-Length/SHA/PIN, реальные локальные сетевые соединения с симулированным устройством, 403/409/422, несовместимые и повреждённые образы, таймауты, отмену, потерю ответа, конкурентные операции, совместимость старого CLOCK, автоматические действия и настоящий WinForms-код.

Нативные проверки: 32 случая в реальном ClockConfigValidation.h, 23 проверки реального ClockService.cpp с адаптерами NVS/Wi-Fi/SNTP/времени и четыре исходных теста WheelDetents с макросами Arduino. Они не меняют часы Windows и не обращаются к железу. Два исходных OTA-теста прошивки проходят через pytest. Приложение публикуется self-contained; запуск проверяется с изолированным профилем. Окно OTA отрисовано при масштабе геометрии 100/150%; это не испытание на двух физических мониторах с разным DPI.

Полная сборка ESP32-S3 N16R8 с Hardware CDC, 16 MB flash, OPI PSRAM и двумя OTA-слотами по 7 MiB успешна. Program storage: 1 477 470 байт; статические данные: 58 548 байт. Полученный application BIN: 1 477 616 байт, SHA-256 `087f1f4755b1ca60fd4610c1854caf7d0aead6e0a640df2f1d5ee56623481662`. Этот реальный BIN успешно проверен тем же валидатором MonoPod.Core, который включён в portable-сборку. App descriptor содержит техническую версию `6671d0b` и `arduino-lib-builder`; она не подменяет версию MonoPod из /api/info.

В реальном ELF размер рекурсивного кадра scanFolder — 336 байт, восемь консервативно учтённых кадров — 2688 байт. Это ограничение кадра из дизассемблирования, не доказательство успешной загрузки или запаса стека на плеере.

При сборке использовалась изолированная копия скетча с CSV как partitions.csv. Команда, без загрузки на устройство:

## Проверка на реальном MonoPod пользователем

1. Запустите Desktop 1.2.0 из новой папки, закрыв старый экземпляр. По умолчанию Connect не запускает автоматический сбор медиатеки или установку времени.
2. Откройте Wi-Fi Sync на плеере, подключитесь по показанному IP. Откройте Device → Firmware Update. Проверьте текущие ID, плату, версию, поддержку OTA и размер слота.
3. При 404 сначала нужна USB-прошивка версии с OTA; при отсутствии двойной таблицы разделов — однократная USB-установка правильной таблицы для вашей flash. Desktop этого не выполняет. CSV из комплекта рассчитан только на ESP32-S3 с 16 MB flash.
4. Выберите application/sketch `.bin` под вашу плату и аппаратную конфигурацию. Подключите стабильное питание, введите текущий PIN с экрана, прочитайте предупреждение и подтвердите. Не выбирайте merged, bootloader или partitions.
5. Дождитесь отдельного подтверждения проверки образа и reboot. Вновь откройте Wi-Fi Sync на плеере и нажмите Connect. Desktop покажет версии до/после и сверит ID. Номер с именем BIN не сравнивается. Одинаковая версия не доказывает установку конкретного образа; для расширения NTP дополнительно проверьте наличие `ntp_server` в capabilities.
6. Для часов выполните ручную синхронизацию, сравните показания. Включите нужные автодействия. Задайте NTP-сервер, нажмите Apply, затем проверьте работу после выхода из Sync и переподключения плеера к Wi-Fi, а также после полного отключения питания. Без питания программные часы требуется восстановить из ПК или NTP.

Целостность SHA-256 не заменяет подпись. Клиент не принимает подписанные контейнеры и не проверяет соответствие образа нестандартной распиновке. Проверка версии после reboot не является проверкой хеша запущенного firmware. Сбой питания и корректность загрузки требуют отдельной проверки на конкретном плеере.

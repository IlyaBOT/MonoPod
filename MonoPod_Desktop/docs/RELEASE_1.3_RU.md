# MonoPod Desktop 1.3.0 — MonoPodDB v1 и реальные теги

Обновление 02.11.2026 по MonoPod_Desktop_MonoPodDB_Codex_Task_v0.10.7.0.md. Реальный проект .NET 8/WinForms обновлён на месте. Команды и формат сверены с доступной прошивкой `I:\DIY_iPod_Mono\MonoPod_v0.10.7.1`; прошивка и физический плеер не изменялись.

## Использование

1. Подключиться по USB либо открыть Wi-Fi Sync на плеере и подключиться по его IP. Для USB сначала Start Sync. При capability `library_db_v1` Desktop читает DBINFO и индекс через специальные команды, не открывая каждый аудиофайл ради тегов. Без capability используется прежний обход файлов.
2. **Music → Update Library** или **Sync → Update Library** запускает один refresh и читает готовую БД. Возле Tracks отображается Ready с поколением либо Needs refresh. После пакета загрузок/удалений/переименований refresh выполняется один раз. Если пакет прерван, индекс помечен устаревшим; следующее чтение обновит его.
3. Поля таблиц: имя, размер, тип, дата, теги, длительность, кодек, битрейт, частота, полный CRC32, выборочный CRC32 и путь. **Sample CRC32 — отпечаток первых/последних блоков и размера, не CRC целого файла.** Неизвестный full CRC отображается как —. Даты 0/1980/1981 отображаются как —; выдуманная дата из старого FAT не восстанавливается.
4. В обеих таблицах есть локальный фильтр всех полей и сортировка по заголовкам. При активном индексе DataGridView работает в VirtualMode: строки создаются по мере отображения. Сортировка/фильтр сетевых запросов не отправляют.
5. **Edit Metadata** доступен в контекстном меню, Tools, на Music, по Alt+Enter и двойному клику аудиофайла. Редактируются Title, Artist, Album, Album Artist, Year, Genre, Track Number. Остальные свойства доступны для чтения. Для AAC/WAV запись отключена с пояснением; MP3/FLAC редактируются TagLibSharp 2.3.0, без Python-сервиса.
6. Перед диалогом файл потоково скачивается на диск: максимум 16 KiB за запрос Wi-Fi, 1024 байта USB. Для файлов от 64 MiB запрашивается подтверждение полного скачивания/обратной загрузки. Уже известная локальная копия используется только если её размер и полный CRC совпадают с текущим индексом.
7. Save меняет реальные ID3v2/Vorbis Comment в отдельной копии файла, вычисляет полный CRC и отправляет через существующую атомарную замену `replace=1`. Остальные теги, обложки и total track count не изменяются. Часы перед записью синхронизируются с ПК, если прошивка объявляет clock_sync. До PUT проверяется свободное место: полный новый файл + 64 KiB резерва. Исходник на SD клиент не удаляет.
8. Во время Save показываются байты/проценты, повторный Save запрещён, **Cancel transfer** отменяет операцию через общую машинерию восстановления USB. После подтверждённой записи диалог закрывается, индекс обновляется отдельно. Если чтение индекса затем не удалось, исходная запись не выдаётся за неуспешную загрузку.

## Кэш и восстановление

Кэш лежит рядом с settings.json в `library-cache`, ключ — хеш стабильного ID устройства и generation; каждый файл повторно проверяется по формату/CRC. Признак dirty инвалидирует память/диск логически и требует refresh. При неверной схеме/полях/count/END/CRC/поколении блоки и БД отклоняются, повторов не более трёх. После этого UI включает старый fallback; Update Library повторно пытается включить быстрый индекс.

В доступной 0.10.7.1 `/api/info` не содержит device_guid. Desktop принимает это поле, если оно появится; для Wi-Fi использует hardware DeviceId из OTA INFO, для native ESP USB — серийный номер MAC-формата из Windows PnP. IP/COM не считаются идентификаторами. Если стабильный ID получить нельзя, используется только кэш текущего подключения, без небезопасного повторного применения между плеерами.

В `metadata-recovery/<id>/` сохраняются `original.mp3/flac`, `edited.mp3/flac`, `operation.json` и после подтверждения `committed.txt`. При сбое/отмене они автоматически не удаляются. Частичное скачивание тоже сохраняется. **Tools → Retry prepared metadata upload** выбирает operation.json после переподключения и повторяет подготовленную атомарную замену. Проверяются исходные размер/дата, generation, CRC локального файла и место SD. Если устройство/индекс изменились, операция отклоняется; загрузите актуальную версию файла заново. Исходные локальные выбранные файлы не перезаписываются. Пользователь удаляет recovery-копии самостоятельно после проверки.

## Проверка

Сборка Release и автономная публикация win-x64. Полный набор: **269 тестов**, включая прежние 255. Проверены TSV с русским UTF-8, `+`, `%`, кавычкой, TAB; CRC/поколение/обрезанные блоки, повторный кэш, разные ID, USB Sync gating и сырые бинарные DBREAD, виртуальная таблица/локальный фильтр/один refresh, отказ при нехватке места и разрыв USB с повторной атомарной записью. Legacy-загрузка без атомарной замены запрещена для редактора до любых файловых запросов.

Для настоящих синтетических MP3/FLAC проверены обложка, комментарий, пользовательский тег, total track count и одинаковый SHA-256 декодированного звука до/после. Отдельный **синтетический поток 263 MiB** скачан блоками 16 KiB с проверкой ограниченного роста managed memory; это тест потока, не декодирования настоящего FLAC 263 MiB. GUI-изображения генерируются из настоящих WinForms с эмулятором устройства. TRX/логи находятся в docs/validation-1.3.0.

Физические Wi-Fi/USB тесты на плеере и его microSD не выполнялись. Нужна проверка с реальной 0.10.7.1: первое чтение индекса, повторное подключение, теги большого FLAC, полный контакт/CRC после загрузки и последующее воспроизведение. OTA, темы, Bad Apple, часы и отмена остаются в существующем коде и прежних регрессионных тестах.

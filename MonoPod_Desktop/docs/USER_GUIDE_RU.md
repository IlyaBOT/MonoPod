# MonoPod Desktop — использование

1. Запустите `publish\win-x64\MonoPod.Desktop.exe`. Папку публикации переносите целиком. Python и установленный .NET Runtime не нужны.
2. Для USB подключите **Native USB-C**, выберите USB и COM-порт. USB-UART с `$STATUS` служит диагностической консолью, не синхронизацией. Connect проверяет HELLO и показывает прошивку; USB-подключение не включает Sync автоматически.
3. Нажмите **Start Sync** для доступа к microSD. Плеер остановит аудио и покажет SYNC. Для Wi-Fi сначала откройте Wi-Fi Sync на самом плеере, выберите Wi-Fi в Desktop и введите адрес, показанный плеером. При STA это адрес домашней сети; 192.168.4.1 относится только к резервному AP.
4. Files: откройте папку двойным щелчком или через дерево; используйте Path/Go/Up/Refresh. Папки располагаются первыми независимо от направления сортировки. Доступны New Folder, Upload Files, Download, Rename, Delete и контекстное меню. Удаление запрашивает подтверждение; папка должна быть пустой. Системные каталоги защищены прошивкой.
5. Music → Refresh Library рекурсивно читает /Music. Add Music показывает локальные теги перед импортом. MP3/WAV/FLAC/raw AAC разрешаются согласно возможностям прошивки. M4A/ALAC не поддерживаются. Повторный импорт предлагает Replace/Skip/Cancel с политикой для очереди. Теги, длительность, кодек и параметры показаны отдельными столбцами. `—` означает отсутствие достоверной длительности. Название файла не выдаётся за тег Title.
6. Themes: выберите локальный TTF/OTF, размеры и сглаживание, задайте 12 цветов через HEX или ColorDialog. Выбирайте Main Menu / Settings / Now Playing / Sync Mode для предпросмотра. Read Device Theme читает установленную тему с устройства. Import/Export MPT поддерживает MPT1 и MPT2; экспорт MPT1 сохраняет только 4 старых цвета. Save/Load profile сохраняет JSON с параметрами и глифами. Upload Theme дожидается актуального предпросмотра, использует выбранный транспорт и проверяет тему. В Desktop 1.1 после установки Sync остаётся активным: можно продолжить работу с файлами или завершить её кнопкой End Sync. По Wi-Fi используется специальный маршрут темы; вручную загружать theme.mpt через Files не нужно.
7. Во время передачи видны процент, скорость и оставшееся время. Cancel safely отменяет очередь и сохраняет подключение. При отмене до отправки данных USB-порт остаётся открытым. Если прерван бинарный блок, Desktop 1.1.2 ждёт безопасный интервал до 18 секунд с последней записи, заново открывает порт и восстанавливает прежний режим Sync автоматически. Дождитесь сообщения «Transfer cancelled. USB connection kept»; затем можно работать с файлами без ручного Connect. Очередь не возобновляется, отменённый файл повторно не отправляется. Старый проверенный файл остаётся до commit. Возобновление с середины файла не поддерживается. Если отмена совпала с финальным commit, проверьте целевой файл перед повтором.
8. End Sync или Disconnect безопасно освобождают устройство; закрытие во время операции запрашивает отмену. Для Wi-Fi End Sync останавливает сервер, поэтому повторное подключение требует снова открыть Wi-Fi Sync на плеере.
9. Device → **Synchronize time with PC** устанавливает текущее время компьютера, часовой пояс и выбранные настройки NTP. Та же команда есть в Settings: **Apply clock settings and synchronize now**. По USB при необходимости временно включается Sync и затем возвращается прежний неактивный режим. Это может приостановить воспроизведение. По Wi-Fi нужен открытый Wi-Fi Sync.
10. В Settings все автоматические действия по умолчанию выключены. **Automatically start Sync and load the music index on connection** запускает Sync, пересоздаёт индекс и читает медиатеку в Music. **Automatically synchronize device time with this PC on connection** включает установку времени при подключении. **Device: automatically synchronize time over NTP when joining Wi-Fi** сохраняет NTP-настройки на плеере при подключении или по Apply; после этого плеер синхронизирует время самостоятельно, даже без Desktop. Сервер по умолчанию `pool.ntp.org`. Для отключения уже сохранённого NTP снимите флажок и нажмите Apply. Часовой пояс берётся из Windows; **Select timezone manually** включает ручной выбор из списка. Старые прошивки с `clock_sync` понимают установку времени и встроенный NTP, а изменение сервера требует capability `ntp_server` из подготовленного расширения 0.10.6.6.
11. Device → **Firmware Update…** доступен по Wi-Fi Sync. Откройте Wi-Fi Sync на плеере, подключитесь по показанному IP, проверьте версию/ID/плату и OTA-слот. Выберите локальный application/sketch `.bin`, введите шестизначный OTA PIN с экрана плеера и подтвердите предупреждение о питании. PIN не является паролем Wi-Fi и нигде не сохраняется. Проценты показывают отправленные байты; только отдельный ответ устройства подтверждает проверку образа и запланированную перезагрузку. После reboot вручную снова откройте Wi-Fi Sync на плеере и нажмите Connect: Desktop сверит ID и покажет версии до/после. При таймауте или отмене HTTP результат может быть неизвестен; приложение не обещает откат и не повторяет обновление. Нужна доверенная локальная сеть. Первичная установка двойной таблицы разделов выполняется через USB, без участия OTA.

Начиная с Desktop 1.2.1 строка **Device time** показывает местное время в прочитанном с плеера часовом поясе: например, `2026-11-01 18:50:00 (UTC+03:00)` для Москвы. Служебная строка POSIX `UTC-3` обозначает именно UTC+03:00; раньше Desktop выводил рядом с ней время UTC, что создавало видимость сдвига на три часа. При неизвестном формате пояса явно показывается **Device UTC time** с предложением применить настройки. Выбор другого пояса в списке действует на плеер только после Apply или включённой автоматической синхронизации при подключении.

Начиная с исправления 1.1.1 USB записывает блоки небольшими порциями для совместимости с малой очередью приёмника 0.10.6, поэтому передача медленнее. После ошибки связи приложение выдерживает таймаут старого бинарного приёмника, заново подключается и пытается завершить Sync, затем отключается. При пользовательском Cancel версия 1.1.2 восстанавливает подключение и оставляет ранее активный Sync включённым. До окончания восстановления не открывайте тот же COM-порт в другой программе. Если восстановление не удалось, Desktop явно сообщает об ошибке: проверьте подключение и выполните Connect / End Sync. Потеря последнего подтверждения не доказывает, что сохранение файла не состоялось.

Настройки — `%AppData%\MonoPod\Desktop\settings.json`: транспорт, адреса, COM, локальный каталог, предупреждение USB, вкладка, столбцы и параметры темы. Settings → Reset application settings сохраняет defaults и закрывает приложение. Log → Save log экспортирует текущую сессию. Wi-Fi-пароли Desktop не собирает.

Desktop 1.1 проверен по коду прошивки v0.10.6 и протоколу MPOD1 v4. Поддержка старой прошивки ограничена её capabilities. Для USB выбирайте Native CDC, а не USB-UART: приложение не перебирает порты с переключением DTR автоматически. Desktop не прошивает устройство автоматически. Сборка и программные проверки не заменяют испытания на физическом ESP32-S3.

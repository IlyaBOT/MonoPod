# MonoPod Desktop 1.0 — итог поставки

Нативное приложение C# / .NET 8 Windows Forms и связанная прошивка v0.10.0 реализованы в отдельных деревьях. База прошивки — фактическая v0.9.1.1. Программные проверки и обе Arduino-сборки успешны; испытания физического плеера не выполнялись.

По присланному crash log найден и исправлен регресс запуска v0.9.0: рекурсивный сканер SD расходовал 4416 байт стека на уровень при стеке loopTask 8192 байта. Уже два уровня переполняли стек. Финальный машинный код использует 352 байта на уровень. Совпадающий по SHA-256 ELF, расшифровка, исправление и границы вывода — в [BOOT_REGRESSION_RU.md](BOOT_REGRESSION_RU.md). Реальный запуск после исправления ещё требуется проверить.

## 2. Архитектура

`MonoPod.Core` содержит модели, валидацию путей, CRC32, метаданные, MPT-кодек и общий `IMonoPodTransport`; USB использует SerialPort, Wi-Fi — HttpClient. WinForms отвечает за интерфейс, состояние подключения, очередь и отмену. На устройстве общий SyncFiles реализует операции SD для обоих транспортов с одним владельцем. Подробнее: [ARCHITECTURE.md](ARCHITECTURE.md).

Files содержит дерево и таблицу, сортировку с папками сверху, upload/download, mkdir, rename и удаление с подтверждением. Music показывает теги и технические свойства в отдельных столбцах, предварительный просмотр импорта и очередь Replace/Skip/Cancel. Метаданные читаются диапазонами до 256 KiB, неизвестные значения остаются пустыми. Themes редактирует 12 цветов, TTF/OTF, кириллицу и сглаживание; предпросмотр 160×128 использует экспортируемые 4bpp-глифы и RGB565. Настройки хранятся в JSON в AppData, журнал можно сохранить.

## 3. Протоколы и безопасность передачи

MPOD1 v4 расширяет существующий USB протокол LIST/STAT/META/READ, файловыми операциями, темами и capabilities. Пути передаются как hex UTF-8; данные идут ограниченными блоками. Соответствующие HTTP `/api/fs/*` возвращают те же сущности; download защищён CRC блока, upload проверяет размер и CRC всего файла. MPT2 добавляет 12 цветов и строгую проверку структуры; MPT1 и старые команды/API сохранены с ограничениями возможностей. Полная спецификация: [PROTOCOL.md](PROTOCOL.md).

Подключение USB не включает Sync. Пользователь явно нажимает Start Sync; для Wi-Fi сначала открывает Sync на плеере. Аудио останавливается, нормальное управление блокируется, SD принадлежит одному транспорту. Домашнее STA-соединение сохраняется, AP — резервный вариант. Замена идёт через temp, проверку, backup и журнал восстановления. Отмена прерванного бинарного USB закрывает порт; текстовая команда не добавляется в данные.

## 4. Сборки

Release, Visual Studio 2022 MSBuild и self-contained win-x64 — успешно, без предупреждений/ошибок. Решение открыто в VS 2022 17.14, три проекта загружены, стартовый проект — Desktop. Проверены установленный SDK 9.0.300 и target .NET 8. Команды воспроизведения — [BUILD.md](BUILD.md).

| Arduino-ESP32 3.3.12 | Программа / лимит | Статическая RAM / лимит |
|---|---:|---:|
| S3 N16R8 / native CDC / 16 MB / OPI | 1 454 610 / 3 145 728 байт | 63 020 / 327 680 байт |
| Classic ESP32 / huge_app | 1 455 019 / 3 145 728 байт | 58 428 / 327 680 байт |

Полные логи, [firmware-build-summary.json](firmware-build-summary.json) и SHA-256-манифесты прилагаются. Бинарники, ELF и MAP — в `MonoPod_Desktop/firmware-builds/`. Сборка S3 не содержит определённых символов A2DP/esp_a2d; classic не предоставляет native USB. Эти цифры не измеряют runtime heap и не доказывают работу на плате.

Повторная сборка с сохранённым кэшем заняла 189.24 s для S3 (8 jobs) и 133.10 s для ESP32 (4 jobs). Для повторения есть `tools/build_firmware.ps1`, который сохраняет раздельные build-каталоги и журнал. Первый запуск после переноса исходников требует построения кэша.

## 6. Запуск EXE и состав архивов

Готовое приложение: `I:\DIY_iPod_Mono\MonoPod_Desktop\publish\win-x64\MonoPod.Desktop.exe`.

Переносите всю папку `win-x64`: Python и отдельно установленный .NET Runtime не требуются. Руководство — [USER_GUIDE_RU.md](USER_GUIDE_RU.md).

Поставка в outputs содержит portable ZIP, отдельный ZIP прошивки S3 с ELF/MAP, ZIP всех редактируемых исходников Desktop и новой прошивки вместе с firmware-builds, отдельную копию папки win-x64 и этот отчёт с приложениями. В архив исходников не включены bin/obj, IDE-кэш и промежуточные конфликтные копии. `SHA256SUMS.txt` содержит контрольные суммы архивов и EXE, `PACKAGE_VERIFICATION.json` — проверку состава и целостности. Прошивка автоматически не устанавливается.

## 7. Требуется настоящая ESP32-S3 — UNVERIFIED

1. COM Native USB, HELLO/версия, START/END и восстановление соединения; проверить, что USB-UART остался консолью.
2. Реальный SD upload/download/replace, скорость, CRC после чтения, извлечение кабеля на разных границах блоков и повтор передачи.
3. Эксклюзивность SD, остановка/возобновление аудио, блокировка управления и индекс после Sync.
4. Wi-Fi в существующей LAN, потеря/возврат роутера, резервный AP, длинные передачи.
5. MPT1/MPT2 через оба транспорта, цвета, кириллица, сглаживание и соответствие реальному ST7735S.
6. Питание во время commit/flush/rename на расходной карте с резервной копией: физическая FAT-атомарность не доказана.
7. Runtime heap/PSRAM, крупные темы и индексация на S3 и особенно на classic ESP32 без PSRAM; обычное воспроизведение и управление после завершения.

## 8. Ограничения и оставшиеся проверки

- Физические тесты не выполнены; устройство не прошивалось, SD не форматировалась. Ошибки компиляции и проваленные программные тесты в финальном прогоне отсутствуют.
- Файлы до 1 GiB; путь до 240 UTF-8 байт, компонент до 90. Удаляются только пустые папки. Скачивание папки целиком явно Unsupported. Внутренние каталоги защищены; тема имеет отдельную операцию.
- Передача возобновляется с начала. После обрыва USB подождите 18 секунд перед повторным подключением. При потере последнего ACK commit мог завершиться: сначала проверьте каталог. Журнал не гарантирует защиту FAT/SD-кэша от произвольного пропадания питания.
- Индекс плеера остаётся 2048 треков и прежней глубины; файловый менеджер читает страницы сверх этого количества.
- M4A/ALAC не поддерживаются, AAC — raw ADTS. Некоторые ID3 unsync/encrypted/нестандартные теги не разбираются. Неизвестная длительность остаётся неизвестной; FLAC с sample count=0 не выдаётся за 0 секунд.
- GDI+ и Pillow могут различаться растеризацией одного TTF; формат и набор глифов проверены. Максимальный payload темы 131072 байта; нехватка heap приводит к ошибке активации.
- Старые прошивки ограничены capabilities. Новая палитра требует MPT2; MPT1 содержит четыре цвета. Полные Files и USB Themes требуют v0.10.0.
- HTTP рассчитан на доверенную LAN, без TLS/аутентификации, один клиент с очередью. Автоматическая прошивка не добавлена.
- Живой UI проверен на Windows 11 при 96 DPI; 125/150% проверены логическим Scale. Настоящие системные DPI, несколько мониторов и Windows 10 требуют отдельного испытания.
